# プロンプト (prompt) 機能仕様

## 概要

プロンプトは、対話的な 1 行入力と、入力欄を画面下部へ固定したまま出力を流す画面制御を提供する機能です。  
対象は `cplat/prompt/prompt.h` と `cplat/prompt/pinned_prompt.h` です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
API 契約の一覧と設計メモは `prod/libsrc/cplat/prompt/README.md` を参照してください。

> [!NOTE]
> 固定プロンプトは試験的な機能です。
> 機能仕様の見直しに合わせて、関数、型、挙動を変更する可能性があります。

## 解決する課題

対話的なコマンドライン ツールでは、入力中にもプログラムが出力を書きます。  
何も対策しなければ、入力途中の行に出力が割り込み、入力欄が壊れます。

行編集そのものにも実装の負担があります。

- カーソル移動と削除を UTF-8 の文字境界で行う必要があります。
- 画面幅を超える入力は、横スクロールして表示する必要があります。
- 履歴の呼び出しと復元を、入力欄の再描画と整合させる必要があります。
- 端末のサイズは実行中に変わります。

さらに、パイプへリダイレクトされた場合は、画面制御を行ってはいけません。  
制御シーケンスがそのまま出力に混ざるためです。

本機能は、1 行入力と履歴を基本機能として提供し、その上に入力欄を固定する画面制御を重ねます。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| 1 行を対話的に入力する | 行編集付きの読み取り |
| 過去の入力を呼び出す | 呼び出し元ごとに分かれた履歴 |
| 日本語を含む入力を正しく編集する | UTF-8 の文字境界を保つカーソル移動と削除 |
| 画面幅を超える入力を扱う | 横スクロール表示 |
| 入力中でも出力を表示する | 入力欄を保ったまま書き込む専用出力 API |
| 状態を常時表示する | 上部と下部のステータス行 |
| 端末のサイズ変更に追従する | 読み取り開始時、キー入力時、専用出力時のサイズ確認 |
| 端末でない場合に壊れない | 通常入出力へのフォールバック |
| 入力の終了理由を区別する | 確定、EOF、中断を分ける結果コード |

## 1 行入力と履歴

1 行入力は、行編集と履歴を伴う読み取りを提供します。  
確定は Enter で、`CPLAT_OK` を返します。

入力の終了理由は結果コードで区別します。  
EOF は `CPLAT_ERR_EOF`、Ctrl+C による中断は `CPLAT_ERR_CANCELED` です。  
呼び出し側は、正常な入力、入力の終わり、利用者による中断を分けて扱えます。

履歴は、読み取りを呼び出した箇所ごとに分かれます。  
1 つのプログラムが用途の違う入力を複数持つ場合に、履歴が混ざりません。

履歴の件数、入力バッファーの初期容量と最大容量は、生成時に指定できます。  
0 を指定した項目は既定値を使います。

## 入力欄の固定

固定プロンプトは、入力欄を画面の下部に置き、プログラムの出力をその上へ流します。  
入力中の行が出力に壊されず、入力の途中でも出力を読めます。

出力は専用の API を通します。  
標準出力と標準エラー出力のどちらへ書くかを選べます。  
書き込みは渡されたバイト列だけを出力し、改行を自動では追加しません。

出力の API は入力中でも呼び出せます。  
描画の操作はハンドル内のミューテックスで直列化するため、入力欄と出力が混ざりません。

上部と下部にステータス行を表示できます。  
ステータス行の配置計算では、色指定の制御シーケンスを表示幅 0 として扱うため、色を付けても桁がずれません。

端末のサイズは、読み取りの開始時、キー入力時、専用出力時に確認します。  
実行中にウィンドウの大きさが変わっても、次の描画で追従します。

## 端末でない場合の扱い

標準入出力が端末でない場合、固定描画は行いません。  
入力は通常の行入力、出力は通常の書き込みに戻ります。  
制御シーケンスがリダイレクト先へ混ざりません。

このとき、入力行が呼び出し側のバッファーに収まらない場合は `CPLAT_ERR_BUFFER_TOO_SMALL` を返し、バッファーを空にします。  
行の残りは次の呼び出しで取得できます。

## 適用範囲外

次の項目は本機能が扱いません。

- `printf` や `fprintf` による出力の自動捕捉。出力は専用の API を通します。
- 入力の補完と候補表示。
- 複数行の入力。読み取りは Enter で 1 行を確定する契約を保ちます。
- スクロール可能な履歴ビュー。
- 代替画面バッファーへの切り替え。

複数行入力は、読み取りの契約を変えずに別の API として追加する方針です。  
検討中の宣言案は `prod/libsrc/cplat/prompt/README.md` にあります。

## 前提と制約

Windows では、利用側が `activeCodePage=UTF-8` のマニフェストを設定し、コンソールの初期化を呼ぶ前提です。  
呼び忘れても問題が起きにくいように、生成時にも防御的に初期化を呼びます。

出力する文字列では、色指定の制御シーケンスを使えます。  
それ以外の制御シーケンスを混ぜた場合、表示幅の計算が合わなくなります。
