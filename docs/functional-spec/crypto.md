# 暗号 (crypto) 機能仕様

## 概要

暗号は、バイト列の認証付き暗号化と復号、パスフレーズからの鍵の導出、暗号論的に安全な乱数の取得を提供する機能です。  
対象は `cplat/crypto/crypto.h` と `cplat/crypto/random.h` です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
関数の宣言と契約の正本は公開ヘッダーです。

## 解決する課題

暗号ライブラリは、プラットフォームごとに別のものを使うことになります。  
Linux では OpenSSL、Windows では OS が提供する暗号 API です。  
どちらも初期化の作法と呼び出しの手順が異なり、アルゴリズムの指定方法も揃っていません。

暗号の実装には、選択を誤ると安全性が失われる箇所が多数あります。

- 暗号化だけを行い、改ざんの検出を忘れる
- 同じ鍵で同じノンスを再利用する
- 予測可能な乱数を鍵やノンスに使う
- パスフレーズをそのまま鍵として使う

さらに、暗号ライブラリのヘッダーを公開面へ出すと、利用側のライブラリまでその依存を負います。

本機能は、アルゴリズムと形式を 1 つに固定し、選択の余地を残さない形で提供します。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| 両プラットフォームで暗号化を使う | OS ごとの暗号ライブラリへの振り分け |
| 改ざんを検出する | 認証付き暗号 (AES-256-GCM) と認証タグ |
| ノンスの再利用を避ける | セッション識別子と連番から構成するノンス |
| 暗号化しない情報も改ざんから守る | 追加認証データの指定 |
| パスフレーズから鍵を作る | パスフレーズから固定長の鍵を導出する API |
| 推測されない値を作る | OS の暗号論的乱数源からのバイト列取得 |
| 利用側に暗号ライブラリの依存を負わせない | 公開ヘッダーからの暗号ライブラリの排除 |

## アルゴリズムと形式

暗号化は AES-256-GCM、ハッシュは SHA-256 に固定します。  
Linux では OpenSSL、Windows では OS の暗号 API が、それぞれ同じアルゴリズムを提供します。

暗号化の結果は、次の形式のバイト列です。

```text
[暗号文: 平文と同じ長さ] [GCM 認証タグ: CPLAT_CRYPTO_TAG_SIZE バイト]
```

認証タグを常に付けるため、復号では改ざんを検出できます。  
暗号化だけを行って改ざん検出を省く経路は提供しません。

ノンスは 12 バイトで、セッション識別子と連番から構成します。

```text
[セッション識別子: 4 バイト] [連番: 4 バイト] [埋め: 4 バイト]
```

セッション識別子と連番を呼び出し側が指定する形にすることで、同じ鍵に対して同じノンスを再利用しない構成を、呼び出し側が組み立てられます。

追加認証データは、呼び出し側が任意のバイト列を指定できます。  
暗号化しないが改ざんは検出したい情報を、認証の対象に含められます。

## 乱数

鍵、ノンス、セッション識別子のように推測されてはならない値には、暗号論的に安全な乱数を使います。  
本機能は、OS が提供する暗号論的乱数源からバイト列を取得する API を提供します。

標準の `rand()` は使わないでください。  
glibc は 31 ビット、MSVC は 15 ビットしか返さず、いずれも予測可能です。

## 公開面の方針

暗号ライブラリのヘッダーは公開面へ出しません。  
利用側のライブラリが OpenSSL や OS の暗号ヘッダーに依存しなくなります。

## 適用範囲外

次の項目は本機能が扱いません。

- アルゴリズムの選択。AES-256-GCM と SHA-256 に固定します。
- 公開鍵暗号と署名。
- 鍵の保管と配送。鍵の受け渡しは呼び出し側の責務です。
- ノンスの管理。連番の採番と重複の防止は呼び出し側が行います。
- TLS などのプロトコル。

## 前提と制約

同じ鍵に対して同じノンスを再利用してはなりません。  
GCM は、ノンスを再利用すると平文が復元できる形で安全性を失います。

入力の長さには上限があります。  
プラットフォーム間で共通の契約にするため、両プラットフォームのうち厳しい方の限界値を採用します。

パスフレーズから導出した鍵の強度は、パスフレーズの強度を超えません。
