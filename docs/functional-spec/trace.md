# トレース (trace) 機能仕様

## 概要

トレースは、アプリケーションの診断メッセージを、OS のログ基盤、Windows の診断チャネル、ファイル、標準エラー出力へ送る機能です。  
出力先ごとに詳細度を設定し、同じメッセージを複数の出力先へ振り分けます。

## 解決する課題

運用者が参照するログ、開発者向けの詳細診断、起動直後の端末出力では、適切な出力先と詳細度が異なります。  
OS のログ基盤も Linux と Windows で異なります。

ログ ファイルは上限なく増やせず、複数プロセスから共有する場合は追記と世代更新を調停する必要があります。  
本機能は、出力先、詳細度、ファイルの世代管理、並行処理を一つのトレース状態として扱います。

## 出力先と詳細度

| 出力先 | 位置付け | 既定のしきい値 |
|---|---|
| OS のログ基盤 | 運用者が参照する OS 標準のログ | 無効 |
| ETW | Windows の開発者向け診断 | VERBOSE |
| ファイル | ローカルに保持する運用ログ | INFO |
| 標準エラー出力 | 端末での即時確認 | 無効 |

詳細度は、重大度の高い順に CRITICAL、ERROR、WARNING、INFO、VERBOSE、DEBUG の 6 段階とします。  
無効を指定した出力先へは出力しません。

各出力先は、設定したしきい値以上に重大なメッセージだけを出力します。  
OS 側の詳細度が cplat より粗い場合は、複数の cplat の詳細度を同じ OS 側の詳細度へ対応させます。

Linux では ETW へ出力しません。  
Windows でイベント ログを使用する場合は、利用前にイベント ソースが登録されている必要があります。

## ライフサイクル

トレース状態は、生成、設定、開始、出力、停止、破棄の順で使用します。  
生成直後と停止後は、識別名、ファイル、フックを変更できます。

開始中はメッセージを出力できます。  
詳細度のしきい値だけは開始中にも変更でき、変更前後のいずれかで対象になるメッセージを取りこぼさない形で反映します。

破棄は開始中と停止中のどちらでも行え、トレース状態が所有する資源を解放します。

## 並行処理

cplat が並行呼び出しを管理する方式では、複数のスレッドが同じトレース状態を使用できます。  
利用側が管理する方式では、cplat は同じトレース状態のための同期を行いません。

異なるトレース状態は、どちらの方式でも並行して利用できます。

## メッセージの出力

通常のテキストと、バイナリを 16 進数へ変換したテキストを出力できます。  
呼び出し位置を付加する出力と、位置を付加しない出力を選べます。

利用側が時刻を指定しない場合は、出力時の現在時刻を使用します。  
指定した時刻を利用できない場合もメッセージの出力を継続し、現在時刻へ置き換えたことを通知します。

メッセージが cplat の扱える長さを超える場合は、出力先の範囲外へ書き込まず、末尾を切り詰めます。

## ファイル出力

ファイルには一行ずつ追記し、指定した長さの上限に達すると世代を更新します。  
出力先を指定しない場合は、実行ファイルの位置を基準とする既定のローカル パスを使用します。

共有モードでは、複数プロセスの追記と世代更新を調停します。  
共有モードを使用しない場合は、同じパスへ書き込むプロセスが一つであることを利用側が保証します。

## フック

登録したフックは、メッセージを出力するたびに登録順で呼び出します。  
各フックは、次のフックと通常の出力を継続するか、その時点で処理を終了するかを選べます。

## 適用範囲外

- ネットワークを介したログの収集と転送
- 構造化ログのスキーマ
- ネットワーク ファイル システム上のログ ファイル
- ログの解析と検索
- Linux での ETW 出力

## 前提と制約

Windows のイベント ログへ出力する場合は、事前にイベント ソースを登録する必要があります。

利用側が並行処理を管理する方式では、同じトレース状態への呼び出しを利用側が直列化する必要があります。

識別名、ファイル、フックは停止中にだけ変更できます。
