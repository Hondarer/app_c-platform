# 機能仕様

## この文書群の役割

`functional-spec/` は、`cplat` が「どのような要件を、どのような機能で解決しているか」を説明する文書群です。

読者が最初に知りたいことは、関数の引数ではなく、その機能が前提としている利用状況です。  
本文書群は、要件と、その解決策として用意した機能の対応を示し、関数の詳細へ橋渡しします。

## ほかの文書との関係

| 文書 | 扱う内容 | 正本 |
|---|---|---|
| 機能仕様 (本文書群) | 要件と、解決策としての機能 | 本文書群 |
| [API チート シート](../api-cheatsheet.md) | 用途からの API 逆引き | 公開ヘッダー |
| 公開ヘッダー `prod/include/cplat/` | 関数の宣言、引数、戻り値、契約 | 公開ヘッダー |
| Doxygen 生成物 | 公開 API とモジュールの詳細 | ソースのコメント |
| [コーディング規範](../coding-guideline.md) ほかの規範文書 | 実装するときに守る規則 | 各規範文書 |
| `prod/libsrc/cplat/<機能>/*.md` と個別の詳細文書 | 実装方式、データ構造、測定結果 | 各文書 |

機能仕様は、関数の引数と戻り値を再掲しません。  
個々の関数の契約は公開ヘッダーを、API の逆引きはチート シートを参照してください。

機能仕様は、実装のデータ構造やアルゴリズムの詳細も再掲しません。  
実装方式は `prod/libsrc/cplat/<機能>/` に置く文書と、`docs/` 配下の個別の詳細文書を参照してください。

機能仕様は規範を定めません。  
実装時に守る規則は、コーディング規範と各カテゴリの規範文書が正本です。

## 記載の粒度

`prod/libsrc/cplat/` のサブディレクトリ 1 個につき、1 つの Markdown を作成します。  
サブディレクトリが複数の独立した機能を含む場合でも、まとめて 1 つの文書とし、機能ごとの節に分けます。

## 各文書の構成

各文書は、次の見出しで構成します。  
該当する内容が無い見出しは省略します。

1. 概要 - 機能が扱う対象と、この文書の位置づけ
2. 解決する課題 - 機能が無い場合に呼び出し側が負う負担
3. 要件と機能の対応 - 要件と、それを満たす機能の一覧表
4. 機能ごとの節 - 要件、機能、利用上の注意
5. 適用範囲外 - この機能が扱わないこと
6. 前提と制約 - 呼び出し側が守る条件
7. 選択の指針 - 複数の方式があるときの選び方
8. 関連ドキュメント

## 変更時の手続き

機能の追加、削除、変更を行う場合は、該当する機能仕様を同じ変更の中で見直します。  
手続きは [AGENTS.md](../../AGENTS.md) の「機能の増減と機能仕様の同期」に定めます。
