# 基盤 (base) 機能仕様

## 概要

基盤は、cplat のすべての機能が共通して使うエラー表現と、ビルド環境の差異を吸収するマクロを提供します。  
対象は `cplat/base/` の公開ヘッダー群です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
関数とマクロの契約の正本は公開ヘッダー、cplat の実装がこれらをどう使うかの規範は [cplat コーディング規範](../coding-guideline.md) と [プラットフォーム抽象化ガイドライン](../platform-abstraction-guideline.md) です。

## 解決する課題

C の標準関数と OS API は、失敗の通知方法が統一されていません。  
戻り値が -1 のもの、NULL のもの、0 以外を成功とするものが混在し、詳細は `errno`、`GetLastError()`、`WSAGetLastError()`、`getaddrinfo` の戻り値と、それぞれ別の空間に置かれます。

そのため、呼び出し側は次の負担を負います。

- 関数ごとに異なる成否の判定方法を覚える
- 詳細の取得元をプラットフォームごとに書き分ける
- 数値が同じでも意味が異なるエラー値を、取り違えずに扱う
- OS とアーキテクチャーとコンパイラの判定を、処理系依存マクロで各所に書く

基盤は、これらを共通の表現へ寄せ、呼び出し側が判定と分岐を 1 種類の方法で書けるようにします。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| 成否をどの API でも同じ方法で判定する | 共通結果コードと、成功を 1 値に限る規約 |
| 大まかな失敗種別を、詳細を見ずに分岐する | 分類済みの結果コード |
| OS 由来の詳細を取り違えずに保持する | ドメイン付きの詳細エラー |
| プラットフォームに依存せず失敗の要因を判定する | 共通のエラー要因 |
| 詳細を毎回受け取らずに、必要なときだけ取得する | スレッドごとの直前値 |
| 失敗を人間可読の文言で示す | 結果コードと詳細エラーの文字列化 |
| OS とアーキテクチャーの差で分岐する | 正規化した検出マクロ |
| コンパイラの差で分岐する | コンパイラ検出マクロと属性の共通マクロ |
| 共有ライブラリのエクスポートを両プラットフォームで書く | エクスポート マクロの共通テンプレート |
| ライブラリのロードと解放に処理を挟む | ロード / アンロード フック |

## 共通結果コード

cplat の公開 API は、共通結果コード `int` を戻り値とします。  
成功は `CPLAT_OK` (0) だけで、非 0 はすべて「要求した操作が完遂されなかった」ことを表します。  
判定を 1 種類に固定することで、呼び出し側は関数ごとの成否規約を覚える必要がなくなります。

エラーは負値、エラーではない省略は正値の `CPLAT_SKIPPED` (1) です。  
要求を受け付けたうえで適用しなかった場合を、失敗と区別して通知できます。

`CPLAT_ERR_UNKNOWN` (-1) は、分類済みのコードに該当しないその他のエラーです。  
分類済みのコードは、引数と状態、リソースとバッファー、入力解析、制御の課題別に定義します。  
モジュールごとに別のコード体系を設けず、必要な分類は共通の体系へ追加します。

コードの値は ABI として凍結します。  
定義は課題別の帯に分けて並べますが、帯の範囲による判定は契約に含みません。  
種別の判定には、範囲比較ではなく個々のコード名との比較を使います。

CRT ラッパーと Windows API の UTF-8 ラッパーは、元の API の戻り値規約を保存するため、共通結果コードの適用対象外です。  
どちらの規約に従うかは、各関数の Doxygen に明記します。

## 詳細エラーとエラー要因

共通結果コードは種別だけを表し、OS 由来の値は保持しません。  
`errno` と Win32 エラー コードは番号空間が異なり、同じ値でも意味が異なるためです。

OS 由来の詳細は `cplat_error` に保持します。  
`cplat_error` は、値の由来を表すドメイン、対応する共通結果コード、ドメイン固有の生の値の 3 つを持ちます。  
ドメインを併せて保持することで、`errno` と Win32 エラー コード、Winsock エラー コード、`getaddrinfo` の `EAI_*` を取り違えずに扱えます。

生の値を直接比較しなくても済むように、プラットフォーム共通のエラー要因を提供します。  
要因は、対象が存在しない、アクセスが拒否された、再試行が必要、接続が拒否されたなど、呼び出し側の分岐に必要な粒度で定義します。  
呼び出し側は、`ENOENT` と `ERROR_FILE_NOT_FOUND` を書き分けずに、同じ要因で判定できます。

要因の値も ABI として固定し、新しい要因は末尾へ追加します。

## 詳細エラーの直前値

詳細エラーを受け取る出力引数を、すべての呼び出しで用意するのは負担です。  
そこで、詳細を扱う API は、出力引数とスレッドごとの直前値の両方へ同じ内容を記録します。

出力引数に NULL を渡した場合も直前値は更新されるため、失敗したときにだけ詳細を取りに行けます。  
成功時は出力引数と直前値の両方をクリアするため、前回の失敗が残ることはありません。

直前値は次の対応 API の呼び出しで上書きされます。  
スレッドをまたいだ参照と、対応 API 以外の関数を挟んだあとの参照は保証しません。  
確実に保持する場合は、出力引数を使うか、直前値を直ちに複製してください。

## エラーの文字列化

結果コードと詳細エラーは、人間可読の文言へ変換できます。  
ログとメッセージのために、呼び出し側が対応表を持たずに済ませるためです。

結果コードは名称を返し、詳細エラーはドメインに応じた OS のメッセージを呼び出し側のバッファーへ格納します。  
`strerror` の戻り値の生存期間や、`strerror_r` と `strerror_s` の差異は、この機能の内部で吸収します。

## ビルド環境の検出

OS、アーキテクチャー、コンパイラの判定は、正規化したマクロで行います。  
`_WIN32` や `__GNUC__` のような処理系依存マクロを各所へ直接書くと、判定条件が実装ごとにずれるためです。

OS とアーキテクチャーの検出は `platform.h`、コンパイラの検出とインライン属性などの共通マクロは `compiler.h` が提供します。  
どちらのマクロを使うか、どこに分岐を置くかの規範は [プラットフォーム抽象化ガイドライン](../platform-abstraction-guideline.md) に定めます。  
マクロの一覧と選定理由は、ヘッダーに併置した [platform](../../prod/include/cplat/base/platform.md) と [compiler](../../prod/include/cplat/base/compiler.md) を参照してください。

Windows SDK のヘッダーは、取り込み順序と事前定義マクロによって結果が変わります。  
`windows_sdk.h` は、その組み合わせを 1 か所へ固定し、利用側が順序を意識せずに済むようにします。  
詳細は [windows_sdk.h](../../prod/include/cplat/base/windows_sdk.md) を参照してください。

## 共有ライブラリのエクスポート

共有ライブラリのエクスポート指定は、Linux の可視性属性と Windows の `__declspec` で書き方が異なります。  
また、ライブラリ本体をビルドする場合と、利用側がヘッダーを読む場合で、指定を切り替える必要があります。

`dll_exports.h` は、この切り替えをライブラリ名を与えるだけで組み立てられるテンプレートとして提供します。  
cplat 以外のライブラリも、同じテンプレートで自前のエクスポート マクロを定義できます。

## ロードとアンロードのフック

共有ライブラリは、ロード時の初期化とアンロード時の解放を、プラットフォームごとに異なる仕組みで記述します。  
Linux は constructor と destructor 属性、Windows は `DllMain` です。

`shared_lib_lifecycle.h` は、両者を共通のフック関数へ寄せます。  
利用側のライブラリは、フックの本体だけを書けば、両プラットフォームで同じ初期化と解放を行えます。

フックの実行中は、通常のトレース機能が利用できるとは限りません。  
このため、ロードとアンロードのコンテキストで使える診断メッセージ出力マクロを併せて提供します。

## 適用範囲外

次の項目は本機能が扱いません。

- 例外による失敗通知。cplat の公開 API は戻り値で失敗を通知します。
- OS 由来の値そのものを引数や戻り値として受け渡すこと。詳細は `cplat_error` を経由します。
- モジュールごとの独自結果コード体系。分類は共通の体系へ追加します。

## 前提と制約

詳細エラーの直前値はスレッドごとに独立しており、スレッドをまたいで参照できません。

Win32 エラー コードを扱う API は Windows 専用です。  
Linux では、対応するドメインの値が設定されることはありません。

結果コードとエラー要因の値は ABI として凍結しています。  
既存の値の変更はできず、追加は所定の位置への追記に限ります。
