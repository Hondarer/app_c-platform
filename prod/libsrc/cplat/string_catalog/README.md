# string_catalog - 文字列カタログ

`string_catalog` は、文字列定義ごとに処理用の文字列キー、引数の型、項目メタデータ、言語別の文言を定義し、実行時に値を差し込んで文字列を組み立てるモジュールです。  
言語別のリソースには語順だけを持たせ、値の表現は引数の種別が決めます。翻訳で語順が変わっても、ログへ出る値の表現は変わりません。

宣言は `cplat/string_catalog/string_catalog.h` にあります。API の詳細は同ヘッダーの Doxygen コメントを参照してください。  
要件と外部から観測できる振る舞いは [文字列カタログの機能仕様](https://github.com/Hondarer/app_c-platform/blob/main/docs/functional-spec/string_catalog.md) が正本です。

## 責務の境界

このモジュールが定めるのは、言語、引数の種別、書式の構文、結果コードだけです。  
文字列の内容と文字列キーの体系は利用側の資産であり、ライブラリは保持しません。

| 決める主体 | 対象 |
|---|---|
| ライブラリ | 言語の列挙、引数種別の列挙、書式の構文、引数の上限、結果コード |
| 利用側 | 文字列定義の `key`、省略可能な `id`、必須の `brief`、省略可能な `details` と `remarks`、引数のメタデータ、文言、備考、分類値、カタログの記憶域 |

この境界を保つため、次を守ってください。

- カタログをライブラリで保持しないでください。既定のカタログを設けないでください。
- カタログを参照する公開関数は、カタログ識別オブジェクトを第 1 引数で受け取ります。
- 文字列キーの列挙をライブラリで定義しないでください。`int` として受け取ります。
- 分類値を解釈しないでください。意味と有効な範囲は利用側が決めます。値は保持して返すだけです。
- カタログ指定を省略して呼び出すための簡易関数を、ライブラリ側へ置かないでください。利用側の生成物が持ちます。

## カタログの受け渡し

利用側は、文字列キーごとの定義を並べた配列と、任意のインデックス表を 1 つのカタログ識別オブジェクトにまとめ、呼び出しごとに指定します。  
ライブラリは配列を複製せず、ポインターだけを保持します。指す領域は、そのカタログを使用する間ずっと有効である必要があります。

カタログ識別オブジェクトと項目は初期化関数を持たない `const` の値です。項目の引数定義とメタデータはポインターで参照し、参照先はカタログを使用する間ずっと有効にしてください。

文字列キーから項目全体を検索する公開 API は、`id`、`brief`、`details`、`remarks`、引数の定義、分類値、書式、備考をまとめて返します。`id`、`details`、`remarks` は未設定なら NULL です。個別のメタデータだけを参照する API も使用できます。

`key` は処理から項目を参照する文字列キーです。公開 API の入口は、利用者の列挙と添字表に対応する数値の `key` を受け取ります。  
`id` は処理では意味を持たない補足の文字列です。ライブラリは `id` を解釈せず、検索にも使いません。

点検 API は、文字列キーの重複を定義エラーとして通知します。`id` の未設定と重複は検査しません。

インデックス表は、文字列キーをインデックスとして定義の位置を引くための変換表です。範囲外の位置を示す表は、その位置を読み出さずに未登録として扱います。  
インデックス表を変更した場合は、配列と不整合が生じていないことを点検の API で確認してください。

書式の展開側からカタログを直接参照せず、`cplat/string_catalog/catalog_internal.h` の関数を経由してください。カタログの構造の変更が、書式の展開へ波及しないようにするためです。

## 言語

出力言語はプロセスで 1 つです。組み立ての API へ言語引数を追加しないでください。

ニュートラル言語以外の要素が NULL の場合は、ニュートラル言語の要素へフォールバックします。ニュートラル言語の要素は NULL にできません。  
言語の列挙を増減した場合は、生成器の定数 `LANGUAGES` を同じ変更で更新してください。

## 書式と引数

書式には、位置指定とエスケープ以外の構文を追加しないでください。値の文字列表現は引数の種別が決めます。

引数の上限は 50 個で、インデックスは 0 起点の `{0}` から `{49}` です。書式解析は 10 進数 2 桁までを受け付け、先行ゼロを含むインデックスを認めません。

上限を変更する場合は、カタログ 1 件分のサイズと、組み立て 1 回あたりのスタック消費量が上限に比例することを考慮してください。値の配列は、実際の引数の個数ではなく上限の個数分をゼロ初期化します。100 を超える値にする場合は、書式解析の桁数の上限も合わせて拡張してください。

引数の種別を追加する場合は、可変長引数の取り出し、値の文字列表現、公開ヘッダーの対応表、生成器の `ARGUMENT_TYPES` を同じ変更で更新してください。既定引数拡張と一致しない `va_arg` の指定を追加しないでください。

## 実装の構成

処理は次の 3 段で進みます。

```text
                  文字列キー
                       |
          +------------+------------+
          |                         |
     引数スキーマ              言語別リソース
          |                         |
     { STRING,               日本語: "...{1}...{0}"
       ERROR_CODE }          英語:   "...{0}...{1}"
          |                         |
          +------------+------------+
                       |
                       v
              可変長引数の取り出し
                       |
                       v
              値の配列 (最大 50 個)
                       |
                       v
              位置指定書式の展開
                       |
                       v
                UTF-8 の文字列
```

| 段 | 実装 | 責務 |
|---|---|---|
| 入口 | `string_catalog_format.c` | 引数検査、カタログの取得、言語別リソースの選択、下位 2 段の呼び出し |
| 検索 | `string_catalog_catalog.c` | 渡されたカタログに対する、文字列キーによる検索 |
| 取り出し | `string_catalog_argument.c` | 引数スキーマに従って `va_arg` の型を選び、値の配列へ写す |
| 展開 | `string_catalog_render.c` | 位置指定を値の文字列表現へ置き換える |

`va_arg` の型指定は取り出しの段だけに現れます。ほかの段は値の配列だけを扱うため、可変長引数の制約から独立します。  
値の配列を経由することで、位置指定の並べ替え、同じ位置指定の繰り返し参照、可変長引数を持たない入力源への将来の転用が可能になります。

既定引数拡張によって `char` と 8 bit、16 bit の整数は `int` へ、`float` は `double` へ昇格します。  
そのため 8 bit と 16 bit の種別は `int` として取り出し、種別が表す幅へ変換してから格納します。昇格後の型と一致しない `va_arg` の指定は行いません。

言語の設定は同期を持たないプロセス グローバルな状態で、`string_catalog_language.c` が保持します。

## 値の文字列化

整数系の種別は、10 進数と 16 進数への変換を `string_catalog_render.c` が自前で持ちます。  
`cplat_snprintf` を使うのは倍精度浮動小数点数だけです。有効桁を保つ丸めを自前で持つ価値がないためです。

自前で持つのは、書式化関数の呼び出しが 1 引数あたりの支配的なコストだからです。  
引数 1 個の書式を 500 万回組み立て、3 回の最良値で測った結果です。単位はナノ秒です。

| 種別 | 書式化関数 | 自前 |
|---|---|---|
| 引数なし | 32.8 | 35.5 |
| STRING | 37.8 | 41.4 |
| SIZE | 93.5 | 45.1 |
| INT32 | 94.7 | 47.9 |
| UINT64 | 102.1 | 56.7 |
| HEX64 | 124.8 | 51.3 |
| POINTER | 127.2 | 50.8 |
| ERROR_CODE | 146.6 | 47.2 |
| DOUBLE | 259.8 | 259.9 |

計測条件は x86_64 Linux、GCC の `-O2` です。MSVC では計測していません。

変換結果が標準ライブラリと一致することは、`stringCatalogRenderTest` が境界値で確認します。`INT64_MIN`、`UINT64_MAX`、負のエラー コードを含みます。  
符号付きの絶対値は `(uint64_t)0 - (uint64_t)value` として求め、最小値での符号反転のオーバーフローを避けています。  
変換関数は書き込んだ長さを返すため、書き込んだ直後の文字列をもう一度走査する `strlen` は不要です。

値の配列は、実際の引数の個数ではなく上限の個数ぶんをゼロ初期化します。そのため上限を大きくしすぎると、組み立て 1 回あたりの固定費が増えます。

| 上限 | 10 | 32 | 200 |
|---|---|---|---|
| ns/回 | 32.8 | 32.1 | 45.1 |

計測条件は、引数を取らない短い書式を 2000 万回組み立て、5 回の最良値を 3 試行で確認したものです。  
上限 32 は上限 10 と差がなく、増分が見え始めるのは 64 を超えたあたりです。

## 生成器

カタログ定義 (JSONC) から、文字列キーの列挙、カタログの表、簡易関数、型付きラッパーを書き出す生成器を `bin/string_catalog_gen.py` に置いています。  
利用側の app が、自身の `makepart.mk` から makefile のパース時に呼び出します。

生成物が依存してよいのは、cplat の公開ヘッダーと標準ヘッダーだけです。特定の app の型や列挙へ依存させないでください。生成物をどの app からもそのまま持ち運べるようにするためです。

型付きラッパーの関数名には `cplat_` を前置しません。利用者が定義した文字列の組み立て関数であり、cplat のリンカー名前空間に属さないためです。名前は文字列キーの定数名を小文字化したもので、定義ファイルの名前に由来するモジュール接頭辞を含みます。

生成ソース内の補助マクロにも、定義ファイルの名前に由来するモジュール接頭辞を付けます。複数のカタログ生成物を同じビルドへ取り込んだ場合も、補助マクロの名前空間を分離するためです。

### カタログ定義の種別

カタログ定義は、`kind` に `message` または `trace` を書きます。省略した場合は `message` です。1 つの定義ファイルが 1 つのカタログに対応し、1 つのカタログが 1 つの種別を持ちます。

| 観点 | `message` | `trace` |
|---|---|---|
| 生成物の出力先 | 呼び出し側のバッファー | トレーサーのハンドル |
| 呼び出し位置の付与 | 付与しません | マクロで付与します |
| 文脈引数 | 持ちません | 引数配列の 40 番から 6 個を出力します |
| 分類値の記載 | `category` へ整数で記載します | `level` へ `cplat_trace_level` の名前で記載し、生成器が整数へ変換します |
| `id` | 省略できます | 必須です |
| 生成物が参照するヘッダー | 文字列カタログの公開ヘッダー | 文字列カタログ、トレース、実行時支援の公開ヘッダー |

トレース種別では、呼び出し位置と実行文脈を引数配列の 40 番から並べます。利用者が記載した引数は 0 番から 39 番までで、その間に残るインデックスは値を受け取らない引数種別になります。文脈引数を通常の引数として扱うことで、条件式による絞り込みが利用者の引数と同じ構文で参照できます。

文脈引数は `source_file_path`、`source_file_name`、`source_line`、`function_name`、`process_id`、`thread_id` です。前の 4 つは呼び出し位置で確定するためマクロが渡し、残る 2 つは実行時の値のため型付きラッパーの内部で取得します。

言語別の書式が文脈引数の位置指定を書いていない場合、組み立てた文字列に文脈値は現れません。出力へ含める必要が生じた場合は、定義の書式へ位置指定を追加します。実装の変更は不要です。

生成器を変更した場合は、その単体テストを実行してください。

```bash
cd bin && python3 -m unittest test_string_catalog_gen
```
