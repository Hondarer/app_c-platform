# 文字列カタログ (string_catalog) 機能仕様

## 概要

文字列カタログは、定義ごとに `key`、`id`、引数スキーマ、分類値、`brief`、`details`、`remarks`、言語別の書式をまとめた集合です。  
`key` は処理から項目を参照する数値の文字列キーで、定義間で一意です。`id` は処理では意味を持たない補足の文字列で、解釈も点検もしません。  
cplat の文字列カタログ機能は、利用側が用意したカタログを受け取り、文字列キーから定義を引き、定義の整合を点検します。  
さらに、文字列キーと利用側が並べた値から、現在の出力言語の文字列を組み立てます。

語順は言語別の書式が決め、値の文字列表現は文字列キーの引数スキーマが決めます。  
出力する言語はプロセスに 1 つで、選んだ言語の資源が未定義の文字列ではニュートラル言語へフォールバックします。

## 解決する課題

文字列の文言、引数の型、分類を製品コードへ直接記述すると、同じ文字列の情報が複数の場所へ分かれます。  
翻訳の追加や分類の見直しのたびに、離れた場所を同時に変更する必要があります。

文字列の定義をライブラリ側で保持すると、利用側は文字列を追加するたびにライブラリを変更することになります。  
文字列キーの名前と値も、ライブラリが決めた体系に縛られます。  
文字列の分類をライブラリが定めると、用意された区分に合わない運用でも、利用側はその区分へ寄せる必要があります。

カタログは、表計算などの定義から生成する対象です。  
生成した定義と、文字列の組み立てが要求する条件に不整合が生じても、実際に組み立てるまで検知できません。  
文字列の種類が増えると、文字列キーから定義を引く走査の対象も増えます。

書式指定を含む文字列をそのまま翻訳の対象にすると、語順の変更に伴って値の並び順も変わります。  
翻訳された書式と、呼び出し側が並べた値の型が食い違うと、出力の誤りでは済まず、実行が壊れます。  
値を順番にしか取り出せない仕組みでは、書式の側から取り出す順序を変えられません。

書式に値の表示形式を書けるようにすると、言語ごとに表現が変わります。  
同じ値が日本語では 16 進数、英語では 10 進数で記録されると、記録の解析が言語に依存します。

文字列を組み立てるたびに言語を指定すると、言語の受け渡しが呼び出しの経路全体へ波及します。  
障害を検出した箇所は、どの言語で出力するかを知らないことが多く、そのためだけに引数を増やすことになります。  
翻訳はすべての言語へ同時に追いつくとは限らず、選んだ言語の資源が未定義のときに出力できないと、翻訳の遅れが障害の記録を失わせます。

cplat の文字列カタログ機能は、定義の所有を利用側へ残したまま受け取り、検索、点検を担い、値の並び順と表現を文字列キーの側へ固定して、書式には語順だけを残します。  
言語はプロセスの設定として 1 か所に集め、未定義の資源のフォールバック先を固定します。

## カタログの受け取りと検索

利用側は、文字列キーごとの定義を並べた集合と、任意の検索用の表を 1 つのカタログにまとめ、要求ごとに指定します。  
カタログは保持しません。そのため、同じプロセスで複数のカタログを扱え、一方への要求が他方の結果を変えることはありません。

定義を複製しないため、指定する領域はそのカタログを使用する間ずっと有効である必要があります。

指定されたカタログが参照できる形でない場合は、要求を行わずに指定が不正であることを通知します。  
参照できない形とは、カタログが無い、定義の集合が無い、要素数が負のいずれかです。

指定の時点では内容を点検しません。点検は利用側が明示的に要求します。  
カタログを渡す手間を省く仕組みは利用側が用意します。既定のカタログを持ちません。

既定では、定義の全件を走査して文字列キーの一致を調べます。  
利用側は、文字列キーをインデックスとして定義の位置を引く表を添えられます。  
表を添えた場合は、全件の走査を表による直接の参照へ置き換えます。表は文字列キーが小さい非負整数である場合に使用できます。

表の内容は利用側が用意するため、参照する前に値の範囲を確認します。  
定義の範囲外を示す値を格納した表を与えても、カタログの外を読み出しません。

項目を識別するのは文字列キーだけです。`id` は項目を取得したあとに参照できる補足の文字列で、検索にも点検にも使用しません。

### 定義の点検

点検は、すべての定義を走査し、次の条件を確認します。

- 書式が構文として正しいこと
- 書式の位置指定のインデックスが、引数の個数に収まること
- 書式の位置指定が、値を受け取らないインデックスを指していないこと
- 引数の個数が上限に収まること
- 文字列キーがほかの定義と重複していないこと
- 引数がある場合、引数定義配列の種別、名前、説明が定義されていること
- 表を添えた場合、各文字列が表を通して自分自身の定義へ到達すること
- ニュートラル言語の書式と備考が揃っていること

点検は、現在の出力言語だけでなく、すべての言語の資源を対象とします。  
ニュートラル言語以外の資源は未定義であってもフォールバックの対象になるため、未定義であること自体は条件の違反ではありません。

表からの到達を確認することで、表と定義の集合が食い違った状態と、文字列キーの重複を検出できます。  
項目メタデータ、引数の個数、引数定義、表からの到達に関する違反は言語に依らないため、特定の言語を通知しません。  
`id` と分類値は解釈しないため、点検の対象にしません。`id` は未定義や重複があっても条件の違反ではありません。

カタログは受け取った時点で内容が確定します。  
点検は起動時に一度実行すれば十分であり、文字列を組み立てるたびに実行する必要はありません。

### メタデータの参照

カタログは、書式のほかに次のメタデータを保持します。  
`brief` は必須の短い説明です。`details` と `remarks` は省略でき、設定した場合はそれぞれ詳細説明と補足説明として保持します。

| 項目 | 内容 | 言語による違い |
|---|---|---|
| `id` | 処理では意味を持たない補足の文字列です。省略できます。 | ありません |
| 分類値 | 利用側が意味を決める整数の補足情報です。 | ありません |
| `brief` | 文字列の用途を短く説明する情報です。 | ありません |
| `details` | 文字列の処理内容を説明する情報です。省略できます。 | ありません |
| 引数の定義 | 引数の種別、名前、説明です。 | ありません |
| `remarks` | 文字列に関する追加の説明です。省略できます。 | ありません |
| 備考 | 引数の単位や出力条件など、書式には含めない補足です。 | 現在の出力言語のものを返します |

分類値は解釈しません。  
重大さの段階、用途、出力先など、値の意味と有効な範囲は利用側が決めます。値を検査せず、保持した値をそのまま返します。

分類なしを表す値は 0 です。  
利用側が 0 を意味のある分類値として割り当てることもできますが、その場合は未登録の文字列キーと区別できません。  
区別が必要な場合は、利用側が先に項目の取得で存在を確認します。

未登録の文字列キーでは、項目が存在しないことを通知します。

## 出力言語の選択

出力言語はプロセスに 1 つです。  
プロセスの初期化時に設定し、文字列を組み立てる箇所では言語を意識しません。

設定していないプロセスの出力言語はニュートラル言語です。  
扱う言語に含まれない指定では設定を変更しないため、指定に失敗しても直前の言語で出力を続けられます。

ニュートラル言語は、次の 2 つを兼ねます。

| 役割 | 内容 |
|---|---|
| 既定の出力言語 | 出力言語を設定していないプロセスが使用します。 |
| フォールバック先 | 出力言語の資源が未定義の文字列で使用します。 |

書式と備考は、資源ごとにフォールバックします。  
書式だけを持ち備考を持たない言語では、書式はその言語のものを使用し、備考はニュートラル言語のものを使用します。

ニュートラル言語の資源が未定義であるとフォールバック先が失われるため、定義の点検は、ニュートラル言語の資源が定義されていることを条件に含めます。

フォールバックは、翻訳が完了していない言語でも文字列を出力するための仕組みです。  
どの言語を選んでも、文字列の引数の表現は変わりません。

## 文字列の組み立て

利用側は、文字列キーの引数スキーマが定める順序で値を並べます。  
語順が異なる言語へ切り替えても、この順序は変わりません。

書式は、位置指定のインデックスによって値を選びます。  
そのため、書式の側では値の並べ替えと繰り返しの参照ができます。

```text
引数スキーマ    : 0 番目 = ファイル名、1 番目 = エラー コード
利用側が並べる値: "config.json", 2
ニュートラル言語: "Failed to open file {0}. Error code={1}"
日本語          : "ファイル {0} を開けませんでした。エラー コード={1}"
```

### 書式の構文

書式が解釈するのは、位置指定とエスケープだけです。

| 記法 | 意味 |
|---|---|
| `{0}` から `{49}` | インデックスに対応する値を、引数種別が定める表現で展開します。 |
| `{{` | `{` を 1 文字出力します。 |
| `}}` | `}` を 1 文字出力します。 |

インデックスは 0 から始まり、10 進数で 2 桁までを受け付けます。  
先頭がゼロのインデックスは認めません。同じインデックスの書き方を 1 通りに保つためです。

3 桁以上のインデックス、先頭がゼロのインデックス、数字以外のインデックス、引数の個数を超えるインデックス、値を受け取らないインデックス、対を成さない中かっこは、いずれも定義の誤りとして扱います。  
表示形式を指定する記法を持たないのは、同じ値の表現が言語によって変わることを防ぐためです。

### 値の文字列表現

引数種別は、値として受け取る型と文字列表現を 1 つに定めます。  
型と表示形式を別々に選べるようにすると、文字列を 16 進数で表すような、意味を持たない組み合わせを表現できてしまいます。

| 引数種別 | 文字列表現 | 例 |
|---|---|---|
| 文字列 | 受け取った文字列をそのまま出力します。値が無い場合は `(null)` を出力します。 | `config.json` |
| 文字 | 印字できる場合は単引用符で囲んだ 1 文字。印字できない場合は 10 進数と 16 進数の併記 | `'A'` / `138 (0x8a)` |
| 符号付き 8 bit 整数 | 10 進数 | `-12` |
| 符号なし 8 bit 整数 | 10 進数 | `200` |
| 符号付き 16 bit 整数 | 10 進数 | `-1200` |
| 符号なし 16 bit 整数 | 10 進数 | `48000` |
| 符号付き 32 bit 整数 | 10 進数 | `-12` |
| 符号なし 32 bit 整数 | 10 進数 | `12` |
| 符号付き 64 bit 整数 | 10 進数 | `-4294967296` |
| 符号なし 64 bit 整数 | 10 進数 | `4294967296` |
| 8 bit の 16 進数 | 2 桁の 16 進数 | `0x8a` |
| 16 bit の 16 進数 | 4 桁の 16 進数 | `0xbeef` |
| 32 bit の 16 進数 | 8 桁の 16 進数 | `0x1234abcd` |
| 64 bit の 16 進数 | 16 桁の 16 進数 | `0x00000000deadbeef` |
| 要素数またはバイト数 | 10 進数 | `4096` |
| 符号付きの要素数またはバイト数 | 10 進数 | `-1` |
| アドレス | アドレスの幅に合わせた桁数の 16 進数 | `0x00007fffa1234567` |
| 倍精度浮動小数点数 | 有効な桁を保つ短い表現 | `12.5` |
| エラー コード | 10 進数と 16 進数の併記 | `2 (0x00000002)` |

16 進数の桁数は引数種別ごとに固定し、英小文字で出力します。  
エラー コードは、Linux の `errno` と Windows のエラー コードのどちらも同じ整数として受け取り、値の変換や説明文の付加を行いません。

8 bit と 16 bit の整数は、可変長引数の既定の型変換によってより大きい型へ変換されます。  
これらの引数種別は、変換後の型で値を受け取ったあと、種別が表す幅へ戻してから表現を決めます。  
変換後の型と一致しない受け取り方をすると、利用側が値を渡した時点で実行が壊れます。

単精度浮動小数点数の引数種別を設けていないのは、変換後の倍精度として扱えば足りるためです。

文字の引数種別は、印字できるかどうかをロケールに依らず判定します。  
判定をロケールに委ねると、同じ値の表現が実行環境によって変わります。

符号付きの要素数またはバイト数は、幅が処理系で異なる型を避け、64 bit の符号付き整数として受け取ります。  
対応するプラットフォームのどちらでも同じ幅になり、値の範囲が実行環境によって変わりません。

### 値を受け取らないインデックス

引数スキーマは、値を受け取らないインデックスを持てます。  
利用側はそのインデックスの値を渡さず、書式もそのインデックスを参照できません。

これは、引数の並びの途中に、あとから用途を割り当てる余地を残すためのものです。  
値を受け取らないインデックスの前後にある引数は、利用側が並べる順序のまま受け取ります。

### 失敗時の振る舞い

| 条件 | 格納先 | 利用側への通知 |
|---|---|---|
| 格納先の指定が無い、または容量が 0 | 変更しません | 引数が不正であること |
| 文字列キーが未登録 | 終端された空の文字列にします | 未登録であること |
| 書式の構文またはインデックスが不正 | 終端された文字列にします | 定義が不正であること |
| 結果が容量に収まらない | 収まる範囲まで格納します | 切り詰めたこと |

切り詰めた結果も終端された文字列であり、利用側はそのまま出力できます。  
切り詰めは組み立ての失敗であり、記録の欠落として扱えます。

### プラットフォーム間の差

アドレスの表現は、環境が定める既定の表記ではなく、アドレスの幅に合わせた桁数の 16 進数へ揃えます。  
これにより、Linux と Windows で同じ値のアドレスが同じ文字列になります。

出力は UTF-8 です。  
端末が UTF-8 以外の符号化を使う場合、文字化けの回避は利用側が行います。

## 適用範囲外

- 表計算などの定義からカタログの生成物を作る生成器
- 実行時にファイルや外部の資源からカタログを読み込む機構
- 分類値の意味付けと、有効な範囲の定義
- 文字列の出力先への書き出しと、分類値による絞り込み
- 文字列キーの採番規則と、`id` の決め方
- カタログを省略して呼び出すための、利用側の関数やインターフェースの形態
- 組み立てている最中のカタログの内容の書き換え
- 環境変数、ロケール、利用者の設定からの出力言語の自動判定
- スレッドごと、要求ごと、出力先ごとの言語の切り替え
- 実行時の言語の追加と、外部資源からの翻訳の読み込み
- 言語ごとの文字コード変換
- 複数形、性、数による語形の選択
- 桁区切り、小数点、日時の表記など、地域の慣習に依存する整形
- 値ごとの表示形式を書式で指定する記法
- 50 個を超える引数
- 時刻やプロセス ID など、組み立てが自ら収集する値
- 端末や出力先の符号化の設定

## 前提と制約

利用側は、カタログを使用する間ずっと有効な領域でカタログを指定します。

カタログの内容は、文字列を組み立てている間に変更できません。  
同期を持たず、内容が変わらないことを前提に検索します。

利用側は、ニュートラル言語の書式と備考を欠かさずに定義します。  
ほかの言語の資源は未定義であっても問題ありません。

利用側は、分類値の意味と有効な範囲を定めます。  
値を検査しないため、範囲外の値を扱う責任は利用側にあります。

表を添える場合、利用側は文字列キーを小さい非負整数として割り当てます。

利用側は、プロセスの初期化時に出力言語を設定します。  
設定は同期を持たないため、文字列を組み立てている間に変更できません。

利用側は、文字列キーの引数スキーマが定める順序と型で値を並べます。  
異なる型の値を渡した場合、組み立ての結果は保証しません。

利用側は、格納先の領域と容量を用意します。  
必要な容量は、書式と値の表現から利用側が見積もります。

書式と引数スキーマの整合は、定義の点検で確認します。  
組み立て時に確認するのは、書式の構文と、位置指定のインデックスが引数の個数に収まることだけです。

## 選択の指針

文字列キーが連続した小さい非負整数である場合は、表を添えて検索の走査を避けられます。  
文字列キーが疎である場合や大きい値を含む場合は、表の要素数が増えるため、全件の走査のままにします。

扱うカタログが 1 つだけの場合は、利用側がカタログを補う簡易関数を用意し、呼び出し側でカタログの指定を省略できるようにします。  
ライブラリとアプリケーションがそれぞれ文字列を持つ場合は、カタログを分離し、それぞれに対応した簡易関数を用意します。

値の意味に合わせて引数種別を選びます。  
同じ整数でも、桁数を固定した 16 進数で記録したい識別子と、10 進数で読みたい件数では、選ぶ種別が異なります。

OS が返す誤りの番号には、エラー コードの種別を選びます。  
10 進数と 16 進数を併記するため、Linux の記録と Windows の記録を同じ手順で読み解けます。

読み取ったバイト数のように、負の値で失敗を表す数量には、符号付きの要素数またはバイト数の種別を選びます。  
1 バイトの値をそのまま示したい場合は文字の種別を、ビットの並びとして読みたい場合は 8 bit の 16 進数の種別を選びます。
