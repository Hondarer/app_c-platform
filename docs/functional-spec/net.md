# ネットワーク (net) 機能仕様

## 概要

ネットワークは、IPv4 のソケット通信を Linux と Windows で同じ手順にそろえた機能です。  
対象は `cplat/net/` の公開ヘッダー群で、ソケット、エンドポイント、バイト オーダー変換の 3 つに分かれます。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
実装者向けの規範は [コーディング規範](../coding-guideline.md) の「net カテゴリの公開面の方針」、API の逆引きは [cplat API チート シート](../api-cheatsheet.md) にあります。

## 解決する課題

BSD ソケットと Winsock は、同じ起源を持ちながら細部が食い違います。

- ハンドルの型が異なります。Linux は `int` のファイル記述子、Windows は `SOCKET` です。
- 閉じる関数、非ブロッキングの設定方法、エラーの取得方法が異なります。
- エラー番号の空間が異なり、Winsock の値は Win32 の `GetLastError()` とも `errno` とも別体系です。
- Winsock は明示的な初期化と終了を必要とし、順序を誤ると呼び出しが失敗します。
- 半クローズや非ブロッキング接続のように、意味論そのものが揃わない操作があります。

さらに、システムのソケット ヘッダーを公開面へ出すと、利用側のライブラリまでシステム ヘッダーに依存します。  
その状態では、通信経路をモックへ差し替えた単体テストが成立しません。

本機能は、これらを 1 か所へ集約し、利用側が生のソケット API を直接呼ばずに済むようにします。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| ソケットを型の差なく扱う | 両プラットフォームのハンドルを可逆に格納する共通ハンドル型 |
| アドレスをシステム ヘッダーなしに扱う | IPv4 のエンドポイント型と、文字列および名前からの変換 |
| バイト オーダーを OS API なしに変換する | シフト演算だけで実装した変換関数 |
| 初期化の順序を意識しない | 初回利用時の自動初期化と、アンロード時の自動終了 |
| 失敗の理由をプラットフォーム共通で判定する | ドメイン付きの詳細エラーと共通のエラー要因 |
| ソケット オプションを安全に設定する | 用途ごとの名前付き設定 API |
| 送受信の途中終了を扱わずに済ませる | 指定バイト数を送り切る、受け取り切る API |
| 複数の相手を 1 つのループで待つ | 複数ソケットの受信可能待機 |
| 切断済みの接続へ送信してもプロセスが落ちない | Linux でのシグナル抑止 |
| 意味論が揃わない操作を安全に呼ぶ | 差異を吸収する引数設計と、契約の明示 |

## ソケット ハンドルとエンドポイント

ソケット ハンドルは専用の型で表します。  
実体は Linux のファイル記述子と Windows の `SOCKET` の双方を可逆に格納できる整数型です。  
無効値は専用の定数で表し、`-1` や `INVALID_SOCKET` との数値比較を利用側に書かせません。

アドレスとポートは IPv4 のエンドポイント型で受け渡し、`struct sockaddr_in` を API 境界へ出しません。  
利用側のライブラリがシステムのソケット ヘッダーに依存しなくなるため、通信経路をモックへ差し替えた単体テストが成立します。

エンドポイントのアドレスとポートは、いずれもネットワーク バイト オーダーで保持します。  
ホスト バイト オーダーとの混在を避けるため、値の設定にもバイト オーダー変換を経由します。

文字列表記のアドレスからの変換、名前解決、文字列への整形を提供します。  
名前解決の失敗は、`getaddrinfo` の体系を区別できる専用のドメインで通知します。

## バイト オーダー変換

バイト オーダー変換は、シフト演算とバイト列の再構成だけで実装します。  
`htons` などの OS API を呼ばないため、この変換はシステムのソケット ヘッダーにも Winsock の初期化にも依存しません。  
検証にモックが不要で、条件の網羅も自明に満たせます。

## 初期化と終了

Winsock の初期化と終了は公開 API にしません。  
初回利用時に内部で初期化し、共有ライブラリのアンロード時に終了します。

利用側は初期化の呼び出し順序を意識せず、任意のタイミングで通信 API を呼べます。  
初期化漏れによる失敗は、利用側の責務から外れます。

## ソケット オプション

ソケット オプションは、用途ごとの名前付き API で提供します。  
`level` と `optname` を数値で受け取る汎用 API は公開しません。  
オプション名と値の型の組み合わせを誤る余地がなくなり、システム ヘッダーの定数を利用側へ出さずに済みます。

マルチキャスト グループへの参加と離脱は対で提供します。  
ソケットを閉じれば参加中のグループからは自動的に離脱するため、離脱の API は、閉じる前に明示的に通知したい場合に使います。

## 送受信

接続済みソケットの送受信、宛先を指定する送信、送信元を得る受信を提供します。  
これらは、1 回の呼び出しで一部だけを転送して戻ることがあります。

全量の転送が必要な場合のために、指定したバイト数を送り切る API と受け取り切る API を提供します。  
呼び出し側が残バイト数を管理する繰り返しを書かずに済みます。

受信可能と送信可能の待機は、タイムアウトを指定して行えます。  
複数のソケットのいずれかが受信可能になるまで待つ API もあり、待ち受けと複数接続を 1 つのループで扱えます。

## 失敗の通知

戻り値は共通結果コードで、OS 由来の詳細は詳細エラーの出力引数へ格納します。  
`errno` と `WSAGetLastError()` の値を、引数や戻り値でそのまま受け渡すことはしません。

ソケット関連のエラーは、Linux のソケット `errno`、Winsock、`getaddrinfo` の 3 つのドメインに分けます。  
一般の `errno` とも区別するため、ソケット操作の `EAGAIN` だけを「再試行が必要」として解釈できます。  
同じ `EAGAIN` でも、プロセス生成が返す値は資源の上限超過であり、意味が異なるためです。

プラットフォームに依存しない判定には、共通のエラー要因を使います。  
接続拒否、接続リセット、アドレス使用中などを、`WSAE*` と `errno` を書き分けずに判定できます。

非ブロッキングの接続が完了待ちになった場合は、共通の要因で表します。  
Linux の `EINPROGRESS` と Windows の値の差は、ここで吸収します。

## プラットフォーム差の明示的な吸収

Linux では、切断済みの接続へ送信すると既定でプロセスにシグナルが配信されます。  
接続済みソケットの送信は、送信ごとにシグナルを抑止する指定を行い、利用者が登録したシグナル ハンドラーやシグナル マスクを変更しません。  
シグナルを抑止しても送信エラーは破棄せず、共通の要因で通知します。

受信方向だけを停止する半クローズは、意味論を完全には揃えられません。  
Linux は読み取り方向を停止してハンドルを保持し、Windows はソケットを閉じます。  
そのため、この API はソケットを入出力引数で受け取り、閉じた場合は無効値を書き戻します。  
呼び出し側は、ハンドルがまだ有効かどうかを自分で判断する必要がありません。

シグナルによる中断の扱いは、cplat 全体の規範に従い、この機能に固有の規則は設けません。

## 適用範囲外

次の項目は本機能が扱いません。

- IPv6。エンドポイント型は IPv4 のアドレスとポートだけを保持します。
- TLS などの上位プロトコル。暗号機能は別のカテゴリで扱います。
- 汎用のソケット オプション設定。用途ごとの API に無いオプションは提供しません。
- 送受信の多重化を伴うイベント ループの提供。待機 API は与えたソケットの状態だけを返します。

## 前提と制約

送受信は、呼び出しごとに一部だけを転送して戻ることがあります。  
全量が必要な場合は、送り切る API と受け取り切る API を使ってください。

ソケット オプションの設定は、対象のソケット種別によって効果が異なります。  
種別に適さない設定を行った場合の結果は、OS の挙動に従います。

同一のソケットへの同時呼び出しは、呼び出し側で直列化してください。
