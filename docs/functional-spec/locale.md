# ロケール (locale) 機能仕様

## 概要

ロケールは、プログラムが利用者へ文字列を表示するときに使用する言語を、実行環境から決定する機能です。  
決定した言語は、言語、表記体系、地域を表す言語タグとして利用側へ返します。

特定の自然言語を決定できない場合の結果を、ニュートラルと呼びます。  
ニュートラルは、利用側がフォールバック先を自身で決定するための結果であり、特定の自然言語を指定しません。

## 解決する課題

利用者の表示言語は、Linux と Windows で保持する場所と取得方法が異なります。  
Linux はログイン時に環境変数へ反映した設定を使用し、Windows は利用者ごとの表示言語の設定を OS が保持します。

Windows では、日付や数値の書式に使用する地域設定と、画面やメッセージの表示に使用する言語を別々に設定できます。  
書式側の設定を表示言語として使用すると、表示言語が英語で地域が日本の環境で、表示言語を日本語と判定します。

環境変数の値は、文字コードや修飾子を含む形式と、区切り文字の異なる形式が混在します。  
利用側がこの解釈を個別に実装すると、app ごとに判定結果が異なります。

プロセス全体のロケール設定を変更して言語を調べる方法は、呼び出し元の状態を書き換えます。  
指定されたロケールが導入されていない環境では、指定自体は行われているにもかかわらず、言語を取得できません。

cplat のロケール機能は、環境変数と OS の設定を決まった順序で評価し、正規化した言語タグとして返します。  
プロセスのロケール設定は変更せず、ロケールの導入状態にも依存しません。

## 表示言語の決定

表示言語は、環境変数、OS の設定、ニュートラルの順に評価します。  
先に評価した候補で決定した場合、後続の候補は評価しません。

環境変数は `LC_ALL`、`LC_MESSAGES`、`LANG` の順に評価します。  
この順序は、メッセージの言語を決定する POSIX の規則に合わせています。  
値が空文字列の環境変数は、設定されていない場合と同じく未設定として扱います。

候補が特定の自然言語に属さないロケールの指定である場合は、その時点でニュートラルを結果とします。  
言語を指定しない設定は、言語が不明であることとは異なり、言語に依存しない出力を選択した指定であるためです。

候補を言語タグとして解釈できない場合は、その候補を使用せず、次の候補を評価します。  
解釈できない指定は、利用者の意図を判定できないためです。

環境変数で決定できない場合、Windows では利用者が設定した表示言語を候補とします。  
Linux では、システムの設定がログイン時に環境変数へ反映されるため、環境変数以外の候補を評価しません。

## 言語タグの表記

言語タグは、言語、表記体系、地域の区別を保持し、次の表記へそろえます。

| 区別 | 表記 | 例 |
|---|---|---|
| 言語 | 小文字 | `ja` |
| 表記体系 | 先頭だけ大文字 | `Hans` |
| 地域 | 大文字 | `JP` |

区別の間は 1 文字のハイフンで区切ります。  
`ja`、`ja-JP`、`zh-TW`、`zh-Hans-CN` のような表記になります。

表記体系と地域を保持するのは、同じ言語でも表示する文言が異なる場合があるためです。  
利用側は、必要な範囲の区別だけを参照できます。

ニュートラルの結果は、長さ 0 の文字列で表します。

## 適用範囲外

- 翻訳した文言の保持と、文字列の組み立て
- 日付、時刻、数値、通貨の書式
- 文字コードの変換と、文字列の照合順序
- 表示言語の変更の通知
- 指定されたロケールが実行環境に導入されていることの確認
- 利用者が設定した表示言語の優先順位の一覧の取得

## 前提と制約

環境変数は、Linux と Windows のどちらでも優先して評価します。  
POSIX 互換のシェルが環境変数を設定した Windows 環境では、その指定が OS の表示言語の設定より優先されます。

環境変数は、プロセスの実行中に変更できます。  
取得のたびに評価するため、変更後の取得では変更後の値を使用します。  
他のスレッドが環境変数を変更する場合は、利用側で同期してください。

ニュートラルの扱いは利用側が決定します。  
ニュートラルに対して使用する文言は、この機能の対象ではありません。
