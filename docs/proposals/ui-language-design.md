# 表示言語の取得の設計

> [!NOTE]
> 本書は、実行環境が示す表示言語を取得する `locale` モジュールと、文字列カタログの出力言語との連携に関する設計文書です。  
> 要件と外部から観測できる振る舞いは、[ロケール (locale) 機能仕様](../functional-spec/locale.md) および [文字列カタログ (string_catalog) 機能仕様](../functional-spec/string_catalog.md) が正本です。

## 目的

利用者の表示言語を、Linux と Windows で同じ手順で取得できるようにします。  
最初の利用先は文字列カタログの出力言語の初期値であり、それ以外の用途でも単独で利用できる形にします。

## 対象とする言語

対象は、画面やメッセージの表示に使用する言語です。  
日付や数値の書式に使用する地域設定は対象外とします。

Windows では、表示言語と地域設定を別々に設定できます。  
地域設定を返す `GetUserDefaultLocaleName` を第一の候補にすると、表示言語が英語で地域が日本の環境で日本語と判定します。  
そのため、表示言語の優先順位を返す `GetUserPreferredUILanguages` を第一の候補とします。

## 決定の順序

環境変数、OS の設定、ニュートラルの順に評価します。

```text
LC_ALL -> LC_MESSAGES -> LANG -> (Windows のみ) OS の表示言語 -> ニュートラル
```

環境変数の順序は POSIX の規則に合わせています。  
メッセージの言語は `LC_MESSAGES` カテゴリが決定し、`LC_ALL` が設定されている場合はそれが最優先となるためです。  
値が空文字列の環境変数は未設定として扱います。

環境変数は Windows でも優先します。  
同じ環境変数の指定に対して両プラットフォームが同じ結果を返すため、挙動の説明と検証が単純になります。  
POSIX 互換のシェルが `LANG=C` を設定した Windows 環境では、OS の表示言語ではなくニュートラルになります。  
これは、言語に依存しない出力を選択した指定として扱う判断によるものです。

Linux では、環境変数以外の候補を評価しません。  
`/etc/locale.conf` などのシステム設定は、ログイン時に環境変数へ反映されるためです。

`setlocale` は使用しません。  
プロセス全体のロケール設定を書き換えるうえ、指定されたロケールが導入されていない環境では失敗します。  
コンテナーのように `ja_JP.UTF-8` が指定されていても導入されていない環境では、指定された言語を採用する方が利用者の意図に合います。

## 言語タグの正規化

環境変数の値と OS が返す名前を、同じ規則で正規化します。

| 手順 | 内容 |
|---|---|
| 1 | `.` 以降の文字コードと、`@` 以降の修飾子を取り除きます。 |
| 2 | 残りが `C` または `POSIX` の場合は、ニュートラルとして確定します。 |
| 3 | `_` または `-` で区切り、先頭を言語とします。英字 2 文字から 3 文字を小文字へそろえます。 |
| 4 | 英字 4 文字の区別は表記体系とし、先頭だけ大文字へそろえます。 |
| 5 | 英字 2 文字または数字 3 桁の区別は地域とし、大文字へそろえます。 |
| 6 | 上記に当てはまらない構成は解釈できないものとし、次の候補の評価を続けます。 |

表記体系と地域を保持するのは、同じ言語でも表示する文言が異なる場合があるためです。  
`zh-CN` と `zh-TW` は別の文言を必要とし、Windows が `zh-Hans-CN` の形式で返す場合もあります。  
区別を保持したまま返すことで、利用側が必要な範囲だけを参照できます。

## 文字列カタログとの連携

言語タグから扱う言語への対応付けは、文字列カタログが持ちます。  
言語の列挙は文字列カタログの資産であり、ロケール機能が特定の列挙へ依存しないようにするためです。  
依存の方向は、文字列カタログからロケール機能への一方向です。

出力言語は、最初に使用する時点で実行環境から決定します。  
利用側が明示的に設定した場合は、その設定を優先し、実行環境からの決定を行いません。  
ニュートラル言語を明示的に設定した運用が、実行環境の表示言語によって上書きされないようにするためです。

決定は 1 回だけ行い、以後は保持した値を使用します。  
文字列の組み立てのたびに環境変数を評価すると、同じプロセスの記録が途中で別の言語へ切り替わる可能性があるためです。

複数のスレッドが同時に最初の参照を行った場合、決定の処理が重複して実行される可能性があります。  
いずれのスレッドも同じ値を書き込むため、観測される出力言語は同じです。  
出力言語をプロセスの初期化時に確定させる運用は、従来と変わりません。

## 未確認の事項

Windows の中国語環境で `GetUserPreferredUILanguages` が返す表記は、実機で確認していません。  
`zh-CN` と `zh-Hans-CN` のいずれであっても言語タグとして保持できる正規化としていますが、実機での確認後に必要な調整を判断します。
