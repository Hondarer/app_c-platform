# string_catalog - 文字列カタログ

`string_catalog` は、文字列定義ごとに処理用の文字列キー、引数の型、項目メタデータ、言語別の文言を定義し、実行時に値を差し込んで文字列を組み立てるモジュールです。  
言語別のリソースには語順だけを持たせ、値の表現は引数の種別が決めます。翻訳で語順が変わっても、ログへ出る値の表現は変わりません。

宣言は `cplat/string_catalog/string_catalog.h` にあります。API の詳細は同ヘッダーの Doxygen コメントを参照してください。  
要件と外部から観測できる振る舞いは [文字列カタログの機能仕様](https://github.com/Hondarer/app_c-platform/blob/main/docs/functional-spec/string_catalog.md) が正本です。

## 責務の境界

このモジュールが定めるのは、言語、引数の種別、書式の構文、結果コードだけです。  
文字列の内容と文字列キーの体系は利用側の資産であり、ライブラリは保持しません。

| 決める主体 | 対象 |
|---|---|
| ライブラリ | 言語の列挙、引数種別の列挙、書式の構文、引数の上限、結果コード |
| 利用側 | 文字列定義の `key`、省略可能な `id`、必須の `brief`、省略可能な `details` と `remarks`、引数のメタデータ、文言、備考、分類値、カタログの記憶域 |

この境界を保つため、次を守ってください。

- カタログをライブラリで保持しないでください。既定のカタログを設けないでください。
- カタログを参照する公開関数は、カタログ識別オブジェクトを第 1 引数で受け取ります。
- 文字列キーの列挙をライブラリで定義しないでください。`int` として受け取ります。
- 分類値を解釈しないでください。意味と有効な範囲は利用側が決めます。値は保持して返すだけです。
- カタログ指定を省略して呼び出すための簡易関数を、ライブラリ側へ置かないでください。利用側の生成物が持ちます。

## カタログの受け渡し

利用側は、文字列キーごとの定義を並べた配列と、任意のインデックス表を 1 つのカタログ識別オブジェクトにまとめ、呼び出しごとに指定します。  
ライブラリは配列を複製せず、ポインターだけを保持します。指す領域は、そのカタログを使用する間ずっと有効である必要があります。

カタログ識別オブジェクトと項目は初期化関数を持たない `const` の値です。項目の引数定義とメタデータはポインターで参照し、参照先はカタログを使用する間ずっと有効にしてください。

文字列キーから項目全体を検索する公開 API は、`id`、`brief`、`details`、`remarks`、引数の定義、分類値、書式、備考をまとめて返します。`id`、`details`、`remarks` は未設定なら NULL です。個別のメタデータだけを参照する API も使用できます。

`key` は処理から項目を参照する文字列キーです。公開 API の入口は、利用者の列挙とインデックス表に対応する数値の `key` を受け取ります。  
`id` は処理では意味を持たない補足の文字列です。ライブラリは `id` を解釈せず、検索にも使いません。

点検 API は、文字列キーの重複を定義エラーとして通知します。`id` の未設定と重複は検査しません。

インデックス表は、文字列キーをインデックスとして定義の位置を引くための変換表です。範囲外の位置を示す表は、その位置を読み出さずに未登録として扱います。  
インデックス表を変更した場合は、配列と不整合が生じていないことを点検の API で確認してください。

書式の展開側からカタログを直接参照せず、`cplat/string_catalog/catalog_internal.h` の関数を経由してください。カタログの構造の変更が、書式の展開へ波及しないようにするためです。

## 言語

出力言語はプロセスで 1 つです。組み立ての API へ言語引数を追加しないでください。

ニュートラル言語以外の要素が NULL の場合は、ニュートラル言語の要素へフォールバックします。ニュートラル言語の要素は NULL にできません。  
言語の列挙を増減した場合は、生成器の定数 `LANGUAGES` を同じ変更で更新してください。

## 書式と引数

書式には、位置指定とエスケープ以外の構文を追加しないでください。値の文字列表現は引数の種別が決めます。

引数の上限は 50 個で、インデックスは 0 起点の `{0}` から `{49}` です。書式解析は 10 進数 2 桁までを受け付け、先行ゼロを含むインデックスを認めません。

上限を変更する場合は、カタログ 1 件分のサイズと、組み立て 1 回あたりのスタック消費量が上限に比例することを考慮してください。値の配列は、実際の引数の個数ではなく上限の個数分をゼロ初期化します。100 を超える値にする場合は、書式解析の桁数の上限も合わせて拡張してください。

引数の種別を追加する場合は、可変長引数の取り出し、値の文字列表現、公開ヘッダーの対応表、生成器の `ARGUMENT_TYPES` を同じ変更で更新してください。既定引数拡張と一致しない `va_arg` の指定を追加しないでください。

## 実装の構成

処理は次の 3 段で進みます。

```text
                  文字列キー
                       |
          +------------+------------+
          |                         |
     引数スキーマ              言語別リソース
          |                         |
     { STRING,               日本語: "...{1}...{0}"
       ERROR_CODE }          英語:   "...{0}...{1}"
          |                         |
          +------------+------------+
                       |
                       v
              可変長引数の取り出し
                       |
                       v
              値の配列 (最大 50 個)
                       |
                       v
              位置指定書式の展開
                       |
                       v
                UTF-8 の文字列
```

| 段 | 実装 | 責務 |
|---|---|---|
| 入口 | `string_catalog_format.c` | 引数検査、カタログの取得、言語別リソースの選択、下位 2 段の呼び出し |
| 検索 | `string_catalog_catalog.c` | 渡されたカタログに対する、文字列キーによる検索 |
| 取り出し | `string_catalog_argument.c` | 引数スキーマに従って `va_arg` の型を選び、値の配列へ写す |
| 展開 | `string_catalog_render.c` | 位置指定を値の文字列表現へ置き換える |

`va_arg` の型指定は取り出しの段だけに現れます。ほかの段は値の配列だけを扱うため、可変長引数の制約から独立します。  
値の配列を経由することで、位置指定の並べ替え、同じ位置指定の繰り返し参照、可変長引数を持たない入力源への将来の転用が可能になります。

既定引数拡張によって `char` と 8 bit、16 bit の整数は `int` へ、`float` は `double` へ昇格します。  
そのため 8 bit と 16 bit の種別は `int` として取り出し、種別が表す幅へ変換してから格納します。昇格後の型と一致しない `va_arg` の指定は行いません。

言語の設定は同期を持たないプロセス グローバルな状態で、`string_catalog_language.c` が保持します。

## 値の文字列化

整数系の種別は、10 進数と 16 進数への変換を `string_catalog_render.c` が自前で持ちます。  
`cplat_snprintf` を使うのは倍精度浮動小数点数だけです。有効桁を保つ丸めを自前で持つ価値がないためです。

自前で持つのは、書式化関数の呼び出しが 1 引数あたりの支配的なコストだからです。  
引数 1 個の書式を 500 万回組み立て、3 回の最良値で測った結果です。単位はナノ秒です。

| 種別 | 書式化関数 | 自前 |
|---|---|---|
| 引数なし | 32.8 | 35.5 |
| STRING | 37.8 | 41.4 |
| SIZE | 93.5 | 45.1 |
| INT32 | 94.7 | 47.9 |
| UINT64 | 102.1 | 56.7 |
| HEX64 | 124.8 | 51.3 |
| POINTER | 127.2 | 50.8 |
| ERROR_CODE | 146.6 | 47.2 |
| DOUBLE | 259.8 | 259.9 |

計測条件は x86_64 Linux、GCC の `-O2` です。MSVC では計測していません。

変換結果が標準ライブラリと一致することは、`stringCatalogRenderTest` が境界値で確認します。`INT64_MIN`、`UINT64_MAX`、負のエラー コードを含みます。  
符号付きの絶対値は `(uint64_t)0 - (uint64_t)value` として求め、最小値での符号反転のオーバーフローを避けています。  
変換関数は書き込んだ長さを返すため、書き込んだ直後の文字列をもう一度走査する `strlen` は不要です。

値の配列は、実際の引数の個数ではなく上限の個数ぶんをゼロ初期化します。そのため上限を大きくしすぎると、組み立て 1 回あたりの固定費が増えます。

| 上限 | 10 | 32 | 200 |
|---|---|---|---|
| ns/回 | 32.8 | 32.1 | 45.1 |

計測条件は、引数を取らない短い書式を 2000 万回組み立て、5 回の最良値を 3 試行で確認したものです。  
上限 32 は上限 10 と差がなく、増分が見え始めるのは 64 を超えたあたりです。

## 生成器

カタログ定義 (JSONC) から、文字列キーの列挙、カタログの表、簡易関数、型付きラッパーを書き出す生成器を `bin/string_catalog_gen.py` に置いています。  
利用側の app が、自身の `makepart.mk` から makefile のパース時に呼び出します。

生成物が依存してよいのは、cplat の公開ヘッダーと標準ヘッダーだけです。特定の app の型や列挙へ依存させないでください。生成物をどの app からもそのまま持ち運べるようにするためです。外部へ公開するカタログだけは、app のエクスポート マクロを定義するヘッダーへ依存します。

型付きラッパーの関数名には `cplat_` を前置しません。利用者が定義した文字列の組み立て関数であり、cplat のリンカー名前空間に属さないためです。名前は文字列キーの定数名を小文字化したもので、定義ファイルの名前に由来するモジュール接頭辞を含みます。

カタログ定義の `details`、`remarks`、`texts`、`notes` は、文字列と文字列の配列のどちらでも書けます。配列は空白 1 個で連結します。1 行が長くなる文を分けて書くためのものです。

生成ソース内の補助マクロにも、定義ファイルの名前に由来するモジュール接頭辞を付けます。複数のカタログ生成物を同じビルドへ取り込んだ場合も、補助マクロの名前空間を分離するためです。

### カタログ定義の種別

カタログ定義は、`kind` に `message` または `trace` を書きます。省略した場合は `message` です。1 つの定義ファイルが 1 つのカタログに対応し、1 つのカタログが 1 つの種別を持ちます。

| 観点 | `message` | `trace` |
|---|---|---|
| 生成物の出力先 | 呼び出し側のバッファー | トレーサーのハンドル |
| 呼び出し位置の付与 | 付与しません | マクロで付与します |
| 文脈引数 | 持ちません | 引数配列の 40 番から 6 個を出力します |
| 分類値の記載 | `category` へ整数で記載します | `level` へ `cplat_trace_level` の名前で記載し、生成器が整数へ変換します |
| `id` | 省略できます | 必須です |
| 生成物が参照するヘッダー | 文字列カタログの公開ヘッダー | 文字列カタログ、トレース、実行時支援の公開ヘッダー |

トレース種別では、呼び出し位置と実行文脈を引数配列の 40 番から並べます。利用者が記載した引数は 0 番から 39 番までで、その間に残るインデックスは値を受け取らない引数種別になります。文脈引数を通常の引数として扱うことで、条件式による絞り込みが利用者の引数と同じ構文で参照できます。

文脈引数の位置指定と内容の対応は次のとおりです。前の 4 つは呼び出し位置で確定するためマクロが渡し、残る 2 つは実行時の値のため型付きラッパーの内部で取得します。

| 位置指定 | 引数名 | 引数種別 | 値 |
|---|---|---|---|
| `{40}` | `source_file_path` | `STRING` | 呼び出し位置のソース ファイル。コンパイラへ渡した表記のまま |
| `{41}` | `source_file_name` | `STRING` | 呼び出し位置のソース ファイル名。ディレクトリを除いた表記 |
| `{42}` | `source_line` | `INT32` | 呼び出し位置の行番号 |
| `{43}` | `function_name` | `STRING` | 呼び出し位置の関数名 |
| `{44}` | `process_id` | `UINT32` | 出力を要求したプロセスの ID |
| `{45}` | `thread_id` | `UINT32` | 出力を要求したスレッドの ID |

言語別の書式が文脈引数の位置指定を書いていない場合、組み立てた文字列に文脈値は現れません。出力へ含める必要が生じた場合は、定義の書式へ位置指定を追加します。実装の変更は不要です。

利用者が記載した引数の個数から 39 番までは、値を受け取らないインデックスです。書式から参照すると定義の誤りになります。書式が参照できるのは、利用者の引数と 40 番から 45 番までです。

同じ対応表を生成ヘッダーのファイル コメントへも出力します。定義を書く人が、自分のカタログの生成物だけで番号と内容を確認できるようにするためです。

### app が定める文脈引数

`settings` が指す設定ファイルの `context` 節に書くと、app が定める文脈引数を `{46}` から 4 個まで追加できます。基底は生成器の定数として固定しており、定義には書きません。cplat が定める文脈引数は 40 番から 6 個が上限で、増やす場合は app が書式へ記載した位置指定の意味が変わるため、非互換の変更として扱います。

```jsonc
// app 単位の設定ファイル
{
    "context": {
        "headers": ["example/example_context.h"],
        "arguments": [
            {
                "name": "sequence_number",
                "kind": "INT32",
                "description": "出力ごとに増える番号。",
                "inline_value": "example_next_value()"
            }
        ]
    }
}
```

書式が参照する位置指定は、記載順に 46 から詰めて割り当てます。番号を定義へ書く項目は設けません。ワークスペースは全体を一括でビルドするため、位置指定が利用側の古いバイナリと食い違う状況が起きないためです。

cplat が定めるコンテキスト引数が拡張の基底へ届くと、app が定める番号と衝突します。位置指定は定義の並び順から決まるため、衝突しても書式の検査では気付けません。生成器は読み込みの時点でこの不変条件を検査し、cplat 側を増やした場合はすべてのカタログの生成を止めます。

外部へ公開するカタログでは、取得関数もライブラリの外部へ公開してください。取得式は生成ヘッダーの `static inline` の中で展開され、利用側の翻訳単位から呼び出されます。公開の漏れはリンク時まで現れないため、生成ヘッダーのファイル コメントへも注意を出力します。

値の取得は `inline_value` だけを許し、`macro_value` を拒否します。マクロ経由にすると `_with_source` の仮引数が app の設定によって変わり、生成物の関数シグネチャが読み取りにくくなるためです。

取得式は出力の要求ごとに評価されるため、利用 app は軽量、非失敗、スレッド セーフな取得処理を用意します。引数種別が `STRING` の場合、返すポインターは組み立てが完了するまで有効である必要があります。

外部へ公開するカタログが app の文脈引数を持つ場合、その取得関数もライブラリの外部へ公開してください。取得式は生成ヘッダーの `static inline` の中で展開され、利用側の翻訳単位から呼び出されるためです。

設定ファイルは app 単位で、種別の異なるカタログが共有します。文脈引数を持つのはトレース種別だけのため、文字列リソース種別からの参照では `context` 節を読み飛ばします。

記載する個数は 0 個から 4 個です。トレース種別の引数配列は、記載した個数によらず `{46}` から `{49}` までを常に確保し、記載しなかった番号は値を受け取らないインデックスとして残します。app が定める文脈引数を増減しても、生成物の引数配列の形が変わらないようにするためです。

外部へ公開するカタログでは、app が定める文脈引数の増減が、すでにコンパイル済みの利用側に対する非互換の変更になります。型付きラッパーは `static inline` であり、可変長引数の並びが利用側のバイナリへ焼き込まれるためです。番号空間を確保しても、この制約は変わりません。増減した場合は、利用側の再コンパイルが必要です。

### 全文字列へ共通に前置、後置する文字列

カタログ定義の `text_prefix` と `text_suffix` に書くと、そのカタログのすべての書式へ共通の文字列を前置、後置できます。言語をキーとして書き、生成の時点で各書式へ結合します。ライブラリは結合後の書式だけを受け取るため、組み立ての処理は変わりません。

```jsonc
// カタログ定義
{
    "text_prefix": { "neutral": "#{46} " },
    "text_suffix": { "neutral": " [{41}:{42}]" }
}
```

結合では区切りを挿入せず、単純に連結します。必要な空白や記号は、前置と後置の文字列へ含めます。区切りを共通の側が持つことで、区切りの有無をカタログ単位で決められます。

指定のない言語は、書式と同じくニュートラル言語へフォールバックします。節を書く場合は `neutral` が必須です。特定の言語だけ前置や後置を外す場合は、その言語へ空文字列を書きます。

結合するのは `texts` だけで、`notes` は定義のままとします。`notes` は組み立てた文字列ではなく、定義を読む人への補足であるためです。

位置指定は構文だけを検査し、添字が値を受け取るかどうかは検査しません。共通の前置と後置は、引数定義の異なる複数の書式へ結合されるためです。`{0}` も書けますが、実際に値が現れるかは結合先の書式が持つ引数定義によって決まります。

生成ヘッダーの `@par 書式` と生成ソースのテーブルは、どちらも結合後の文字列を示します。定義ファイルの記述とは表現が変わるため、共通の前置または後置を持つカタログでは、生成物のファイル コメントにその旨を出力します。

### 出力先のトレーサー

トレース種別の生成物は、出力先のトレーサーをカタログ単位で保持します。`<module>_set_tracer()` で設定し、`<module>_get_tracer()` で取得します。呼び出しごとにトレーサーを渡す必要をなくすためです。

未設定のまま出力を要求した場合は、文字列の組み立ても出力も行わず `CPLAT_ERR_INVALID_ARGUMENT` を返します。`cplat_tracer_write_at()` は NULL のハンドルを受け取ると何もせず成功を返すため、そのまま渡すと設定の漏れが成功として隠れます。これを避けるため、生成物の側で失敗として扱います。

設定はスレッド セーフではありません。出力を開始する前に設定し、以降は変更しない使い方を想定しています。

設定を解除する呼び出しは、原則として不要です。トレーサーはプロセスの終了時に cplat が破棄するため、その後に出力を要求する経路がありません。トレーサーを明示的に破棄し、そのあとに出力を要求しうる場合に限り、破棄の前に NULL を設定してください。

### カタログを外部へ公開する

カタログ定義の `export` に公開範囲を書くと、関数の宣言へ app のエクスポート マクロと呼び出し規約マクロを出力します。省略した場合は公開しません。

| 公開範囲 | 公開する関数 |
|---|---|
| `api` | 戻り値が cplat の構造体を指さない関数。`_format`、`_vformat`、`_entry_count`、`_category`、`_id`、`_note`、トレース種別の `_write`、`_set_tracer`、`_get_tracer` |
| `full` | 上記に加え、`_catalog`、`_entries`、`_entry`、`_key_index`、`_key_index_count`、`_verify` |

`api` が構造体を返す関数を公開しないのは、利用側が `cplat_string_catalog` のレイアウトへ依存することを避けるためです。`_verify` を公開しないのは、カタログの点検が提供元の責務であるためです。

マクロの接頭辞と定義元のヘッダーは app 内で共通のため、カタログ定義が `settings` で指す設定ファイルへ置きます。接頭辞からマクロ名を導く規約は、`cplat/base/dll_exports.h` の `CPLAT_DLL_EXPORT(prefix)` と同じです。

```jsonc
// app 単位の設定ファイル
{ "export": { "prefix": "EXAMPLE", "header": "example/example_export.h" } }
```

設定ファイルを変更した場合も生成物を作り直すため、`--if-newer` の比較対象に含めます。

公開ヘッダーは `--header-dir` で別の場所へ出力できます。出力先が公開ヘッダーの置き場所である場合、その位置から利用側の include パスを導き、実装側の取り込みを山括弧の形式にします。

型付きラッパーは `static inline` であり、利用側の翻訳単位で展開されます。呼び先は生成物の簡易関数 `<module>_format` としています。`cplat_string_catalog_format()` を直接呼ぶと、利用側が cplat の関数と構造体のレイアウトへ依存するためです。

生成器を変更した場合は、その単体テストを実行してください。

```bash
cd bin && python3 -m unittest test_string_catalog_gen
```
