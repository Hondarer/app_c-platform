# Win32 UTF-8 ラッパー (win32) 機能仕様

## 概要

Win32 UTF-8 ラッパーは、Win32 API を UTF-8 の文字列で呼び出せるようにする Windows 専用の機能です。  
対象は `cplat/win32/win32.h` が公開する `*U` サフィックスの関数群です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
どの場面で `*U` を使い、どの場面で `*W` を直接呼ぶかの規範は [cplat コーディング規範](../coding-guideline.md) の「Win32 API の UTF-8 ラッパーの適用範囲」にあります。

## 解決する課題

Win32 API の文字列を扱う関数には、ナロー文字版とワイド文字版の 2 つがあります。  
ナロー文字版は現在のコード ページで文字列を解釈するため、日本語環境では cp932 になります。  
UTF-8 の文字列をそのまま渡すと、非 ASCII の文字が壊れます。

ワイド文字版は UTF-16 を受け取るため、文字化けは起きません。  
しかし、UTF-8 を前提としたコードから呼ぶたびに、変換用のバッファーを用意し、変換し、後始末をする定型処理が必要です。  
出力を受け取る関数では、逆方向の変換も要ります。

本機能は、この変換を関数ごとに 1 回だけ書き、利用側からは UTF-8 の関数として見えるようにします。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| UTF-8 の文字列で Win32 API を呼ぶ | 引数と戻り値を UTF-8 で受け渡す `*U` 版の関数 |
| 文字化けを防ぐ | 内部での UTF-16 への変換と、ワイド文字版 API の呼び出し |
| 変換の定型処理を書かない | 変換とバッファー管理の内包 |
| プラットフォーム共通のコードに混ぜない | Linux では何も宣言しないヘッダー |

## 対象の範囲

ラップするのは、文字列を引数または戻り値に持つ Win32 API だけです。  
ファイル、名前付きパイプ、モジュール、コンソール、ボリューム、ライブラリ、プロセス、サービス制御に関する関数が該当します。

文字列を扱わない API はラップしません。  
ハンドルを閉じる、読み書きする、イベントを設定するといった関数は、変換すべきものがないためです。

Linux では、このヘッダーは何も宣言しません。  
利用側は、Windows 専用の処理としてのみ呼び出します。

## 適用範囲外

次の項目は本機能が扱いません。

- 結果コードの正規化。`*U` 版は元の Win32 API の戻り値規約をそのまま保ちます。
- ナロー文字版 API の提供。ナロー文字版は使用しません。
- 文字列を扱わない Win32 API のラップ。
- Win32 の機能そのものの抽象化。プラットフォーム共通の機能は、それぞれのカテゴリが提供します。

## 前提と制約

`*U` 版は、共通結果コードの適用対象外です。  
戻り値の判定は、元の Win32 API と同じ方法で行います。

`*U` を使うのは、その呼び出し箇所に UTF-8 との境界が実際に存在する場合に限ります。  
ワイド文字列のまま処理が完結する箇所で `*U` を経由すると、不要な往復変換が発生します。  
判断の基準と、`*W` を直接呼ぶ場合の記載方法は [cplat コーディング規範](../coding-guideline.md) に従ってください。
