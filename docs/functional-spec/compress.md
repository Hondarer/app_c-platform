# 圧縮 (compress) 機能仕様

## 概要

圧縮は、バイト列を縮めて元に戻す機能です。  
対象は `cplat/compress/compress.h` が公開する `cplat_compress` と `cplat_decompress` です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
関数の宣言と契約の正本は公開ヘッダーです。

## 解決する課題

圧縮の実装は、プラットフォームごとに使えるものが異なります。  
Linux では zlib が広く使えますが、Windows には標準では含まれません。  
Windows が提供する圧縮 API は、呼び出し方も既定の出力形式も zlib とは異なります。

そのまま使い分けると、片方で圧縮したデータをもう片方で展開できません。  
プロセス間や通信で圧縮データをやり取りする場合、これは致命的です。

さらに、展開には元のサイズが必要ですが、生の圧縮形式はそれを含みません。  
呼び出し側が元のサイズを別に運ぶ設計は、取り違えの原因になります。

本機能は、両プラットフォームの出力形式を同じにそろえ、元のサイズを圧縮結果に含めます。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| Windows でも圧縮を使う | プラットフォームごとの実装への振り分け |
| 圧縮したデータを別のプラットフォームで展開する | 両プラットフォームで同一の raw DEFLATE 形式 |
| 展開に必要な情報を一緒に運ぶ | 元のサイズを先頭に付けたペイロード形式 |
| 出力先の容量不足を検出する | 入出力兼用の長さ引数による検査 |

## 出力形式

圧縮の結果は、次の形式のバイト列です。

```text
[元サイズ: uint32_t (ネットワーク バイト オーダー)] [raw DEFLATE データ]
```

本体は RFC 1951 の raw DEFLATE です。  
Linux では zlib、Windows では OS の圧縮 API を使いますが、いずれもこの形式を出力します。  
片方で圧縮したデータを、もう片方でそのまま展開できます。

先頭の元サイズは、展開時に必要な出力バッファーの大きさを、呼び出し側が別途運ばずに済ませるためのものです。  
バイト オーダーはネットワーク バイト オーダーに固定するため、エンディアンが異なる環境の間でも解釈が一致します。

## 適用範囲外

次の項目は本機能が扱いません。

- ストリーミングの圧縮と展開。入力全体を 1 回で処理します。
- 圧縮レベルの指定。
- gzip や zip などのコンテナー形式。出力は独自ヘッダー付きの raw DEFLATE です。
- ファイルの圧縮。対象はメモリ上のバイト列です。

## 前提と制約

元のサイズは 32 ビットで保持するため、4 GiB を超えるデータは扱えません。

出力先のバッファーは呼び出し側が用意します。  
長さの引数は入出力兼用で、入力は容量、出力は実際に書き込んだ長さです。

本機能が出力するバイト列は、先頭に独自のヘッダーを持ちます。  
zlib や `gzip` コマンドがそのまま展開できる形式ではありません。
