# ハッシュ テーブル 機能仕様

## 概要

ハッシュ テーブルは、キーから値を引く表を、内部確保した領域にも呼び出し側が用意した領域にも構築できるようにした機能です。  
対象は `cplat/hashtable/hashtable.h` が公開する `cplat_hashtable_*` の一群です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
関数の宣言と契約の正本は公開ヘッダー、可変長ストレージの実装方式の正本は [hashtable 可変長ストレージの管理方式](../../prod/libsrc/cplat/hashtable/hashtable-storage-allocator.md) です。

## 解決する課題

C で名前から値を引く表を用意する場合、呼び出し側は次の設計と実装を繰り返すことになります。

- ハッシュ値の算出、衝突の解決、削除済みスロットの扱いを毎回書き起こす
- キーや値の長さが可変のとき、文字列の格納領域と空き領域を別に管理する
- 表を共有メモリやファイルへ載せる場合に、ポインターを含まない配置を設計する
- 表を読む側が、更新と削除をどの時点で観測できるかを決める
- 表の件数が実行時にしか決まらない場合の容量不足に対処する

いずれも、表そのものの用途とは無関係な作業です。  
本機能は、これらを表の側の責務として引き受け、呼び出し側にはキーと値の形式、容量方針、変更検知の粒度だけを選ばせます。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| キーで値を出し入れする | チェーン法のハッシュ テーブルと、追加・更新・検索・削除の操作 |
| キーと値の形式を用途ごとに決める | 固定長バイナリ、固定長文字列、可変長文字列からの選択 |
| 表を呼び出し側の領域へ載せる | 外部領域への構築と、管理領域とデータ領域の分離 |
| 保存した表をあとから読み直す | 再接続と、接続時のヘッダー検証 |
| 件数が実行時にしか決まらない | 自動拡張する構築方式と、拡張の上限設定 |
| 生成時に内容が確定する表を配布する | レコード番号を保ったままの直接書き込み |
| 削除を読み取り側が取りこぼさない | 削除の遅延と加齢、および回収操作 |
| 変更の有無と前後関係を判定する | 変更時刻と世代カウンター、およびその粒度の選択 |
| 表全体を走査する | レコード番号による走査と、使用状況での絞り込み |
| 可変長領域の断片化に対処する | 連続領域不足の通知と、明示的な圧縮 |
| 値を型付きのまま直接参照する | 固定長値の格納境界の指定 |
| 壊れた領域を検出する | 接続時の検証と、明示的な整合性検査 |

## キーによる値の管理

キーから値を引く表として、追加、更新、検索、削除を提供します。  
衝突はチェーン法で解決するため、容量に対する使用率が高い状態でも探索が破綻しません。

追加は、既存キーとの重複を `CPLAT_ERR_DUPLICATE_KEY` で通知します。  
既存の有無を呼び出し側が事前に調べずに済ませたい場合は、追加と更新を兼ねる操作を使います。  
この操作は、新規追加と既存更新のどちらであったかを出力引数で返すため、重複も未登録もエラーとして扱いません。

検索は、値への参照を返す経路と、呼び出し側のバッファーへ複製する経路の 2 つを持ちます。  
参照は複製の費用を避けられますが、有効期間の制約を受けます。  
制約は「前提と制約」を参照してください。

## キーと値の格納形式

キーと値は、それぞれ独立に固定長バイナリ、固定長文字列、可変長文字列を選べます。  
表の用途によって、固定長で十分な場合と、長さが揃わない文字列を扱う場合の双方があるためです。

固定長バイナリは、指定したバイト数のバイト列としてそのまま複製します。  
全バイトが 0 の値も有効な値として扱うため、数値や構造体をそのまま格納できます。

固定長文字列は、NUL 終端までを複製し、格納領域の未使用部分を内部で 0 埋めします。  
呼び出し側が固定長まで詰めてから渡す必要はありません。

可変長文字列は、専用のストレージ領域へ詰めて格納し、レコードは位置と長さだけを持ちます。  
これにより、最長のキーや値に合わせて全レコードの領域を確保する必要がなくなります。

## 領域の所有と分離

表は、識別子、ヘッダー、バケット配列、エントリ配列からなる管理領域と、値の配列からなるデータ領域の 2 領域で構成します。  
いずれも、永続化して意味のある状態だけで構成し、アドレス情報や実行時だけのフラグを含みません。  
この方針により、表の内容をそのままファイルや共有メモリへ置けます。

呼び出し側が両方の領域を省略した場合は、内部で 1 回の確保にまとめて構築します。  
一般的な用途では、領域の配置を意識せずに使えます。

呼び出し側が両方の領域を明示した場合は、独立した 2 領域へ構築します。  
データ領域だけをメモリ マップド ファイルなど管理領域と連続しない領域へ置く用途を想定しています。  
片方だけの指定はできません。

外部領域へ構築する場合に必要なバイト数は、設定から算出できます。  
呼び出し側が容量を見積もる必要はありません。

## 保存した表の再接続

構築済みの領域へ、内容を保ったまま再接続できます。  
別プロセスが作成した共有メモリや、ファイルから読み戻した領域を、再構築せずにそのまま表として扱うためです。

管理領域はデータ領域のアドレスを保持しません。  
再接続時のデータ領域は、常に呼び出し側が渡した値をそのまま使います。  
この設計により、プロセスごとにマップ先アドレスが異なる場合でも同じ領域を共有できます。

再接続は、識別子と版番号、ヘッダーの範囲、保存されている設定と件数を検証します。  
不正な領域は `CPLAT_ERR_CORRUPT_DESCRIPTOR` として通知し、表として扱いません。

自動拡張の設定は領域に保存しないため、再接続で復元されません。  
再接続した表は固定容量として扱います。

## 容量方針の選択

表の容量には 3 つの方針があり、件数が決まる時点に応じて選びます。

固定容量は、構築時にレコード数とストレージ容量を確定し、以後は変えません。  
容量が設計時に決まる場合と、外部領域を使う場合に選びます。  
レコード数の不足は `CPLAT_ERR_LIMIT_EXCEEDED`、可変長ストレージの不足は `CPLAT_ERR_STORAGE_FULL` として通知し、暗黙に拡張しません。

自動拡張は、内部確保した領域に限り、追加と更新で不足した領域を再構築または拡張します。  
件数が実行時にしか決まらない場合に選びます。  
拡張の上限はレコード数、キー ストレージ、値ストレージのそれぞれに指定でき、0 は上限なしを表します。  
断片化だけが原因の不足では、容量を増やさずに同容量で詰め直します。

容量の変更を呼び出し側の契機で行う方法もあります。  
内部確保の表はレコード数とストレージ容量を指定して作り直せ、外部領域の表は呼び出し側が用意した新しい領域へ内容を保ったまま作り直せます。  
拡大では既存のレコード番号を保存し、縮小ではすべて無効になります。

生成時に内容が確定する表は、レコード番号を指定してキー、値、使用状況、変更時刻を直接書き込めます。  
この経路は、移行や再構築で番号を保ったままレコードを置くためのものです。  
書き込み先が空でなければ `CPLAT_ERR_DUPLICATE_DEFINITION`、同一キーがすでにあれば `CPLAT_ERR_DUPLICATE_KEY` を返し、既存の内容を上書きしません。

## 削除の観測と回収

削除は、対象スロットを直ちに空へ戻さず、削除済みの状態として残せます。  
表を周期的に読む利用側が、削除されたレコードの存在自体を観測できるようにするためです。  
直ちに空へ戻すと、読み取りの周期の間に追加と削除が起きたレコードは、読み取り側から見て最初から存在しなかったことになります。

削除済みのレコードは、呼び出し側が加齢を進める操作を呼んだときにだけ 1 段階ずつ古くなります。  
表の側が時間を測るのではなく、読み取りの周期を知っている呼び出し側が進行を決めます。  
寿命に到達したレコードは空へ戻り、スロットは別のキーへ再利用されます。

寿命は構築時に指定し、2 以上でなければなりません。  
2 は削除を直ちに空へ戻す指定であり、遅延削除を使わない動作になります。  
3 以上を指定すると、削除直後の加齢は 2 から始まり、加齢のたびに 1 ずつ増え、寿命に達した時点で空へ戻ります。  
`CPLAT_HASHTABLE_LIFETIME_INFINITE` を指定すると、加齢は終端で止まり、空へ戻りません。

削除済みレコードは、加齢を待たずにすべて空へ戻すこともできます。  
また、空きスロットが無いときに、最も加齢が進んだ削除済みレコードを再利用する設定も選べます。  
この設定を有効にすると、削除済みの保持よりも新規追加の成功を優先します。

削除済みの同一キーを追加した場合の振る舞いは、追加のたびに選べます。  
渡した値で上書きして復活させる方式と、削除前の値のまま復活させる方式があります。  
後者は、一時的に削除した項目を元の内容へ戻す用途に使います。

## 変更の検知

表は、最後にキーまたは値が変わった実時刻と、変更のたびに 1 増える世代カウンターを常に持ちます。  
表を読む側が、前回の読み取り以降に変更があったかどうかを、全レコードを比較せずに判定するためです。

実時刻は、時計の巻き戻しによって逆行することがあります。  
変更の前後関係を判定する用途には世代カウンターを使い、実時刻は表示と外部システムとの相関に使います。

変更時刻と世代カウンターの粒度は、表全体だけを持つ方式と、レコードごとにも持つ方式から選べます。  
レコードごとに持つ方式は、変更されたレコードだけを取り出す用途に使えますが、エントリの配置が変わり管理領域が大きくなります。  
表全体の世代カウンターは、粒度の選択に関わらず常に有効です。

## 走査と件数の取得

レコード番号は 1 相対で、内部のスロットと 1 対 1 に対応します。  
1 から容量までを順に指定することで、キーを知らなくても表全体を読み出せます。

使用中のレコードだけを辿るなど、使用状況で絞って走査する場合は、次のレコード番号を返す操作を使います。  
空のスロットを呼び出し側が読み飛ばす必要がなくなります。  
列挙の終了はエラーではなく、レコードの有無を返す出力引数で表します。

使用中、削除済み、空の件数は、領域に保持しているカウンターから取得します。  
スロットを走査しないため、容量に依存せず一定時間で完了します。

## 可変長ストレージの断片化

可変長文字列のストレージは、既存のブロックを動かさずに空き領域から確保します。  
取得済みの参照が、無関係な更新で無効にならないようにするためです。

この方針の代償として、合計の空き容量が足りていても連続領域が不足することがあります。  
固定容量の表では、この状態を `CPLAT_ERR_STORAGE_FULL` として通知します。  
呼び出し側は、明示的な圧縮を実行してから再試行できます。  
圧縮を呼び出し側の契機に限ることで、参照が無効になる時点を呼び出し側が把握できます。

自動拡張の表では、断片化による不足を検出したときに同容量で詰め直すため、呼び出し側が圧縮を呼ぶ必要はありません。

## 固定長値の格納境界

固定長値の格納境界は、構築時に指定できます。  
既定では値を隙間なく並べるため、値への参照は型のアラインメントを満たすとは限りません。  
この場合、呼び出し側は参照を型付きポインターとして扱わず、複製して取り出します。

境界を明示した場合に限り、値への参照がその境界に整列していることを保証します。  
構造体や数値をそのまま参照したい場合に指定します。  
指定できる境界は 2 の冪で、`CPLAT_HASHTABLE_VALUE_ALIGN_MAX` 以下です。

## 領域の健全性検査

外部領域や共有メモリの表は、別のプロセスや過去の版が書いた内容を読むことがあります。  
再接続の検証はヘッダーと設定に限るため、チェーンや空きリストの整合性までは確認しません。

内容全体の整合性は、明示的な検査で確認できます。  
再接続の直後や、領域の由来が信用できない場合に実行します。

## 適用範囲外

次の項目は本機能が扱いません。

- 永続化の入出力。領域をファイルへ書き出し、読み戻す処理は呼び出し側の責務です。
- エンディアン変換。読み戻しは同一環境を前提とします。
- 排他制御。同一の表への同時アクセスは呼び出し側で直列化します。
- レコード番号の永続的な識別子としての利用。番号は有効期間を持つ内部キーです。

## 前提と制約

本機能はスレッド セーフではありません。  
同一の表への同時呼び出しは、呼び出し側で直列化してください。

読み戻しは、同一のビット幅と同一のアラインメント規則を持つ環境を前提とします。  
また、単体型と構造体に同じアラインメント規則が適用される環境を前提とします。

レコード番号は、削除、回収、容量変更、破棄をまたぐと無効になりえます。  
番号を保持する場合は、これらの操作を挟まない範囲で使ってください。  
無効になる操作の一覧は公開ヘッダーを参照してください。

値やキーへの参照は、そのフィールドの更新、回収、再利用、圧縮、容量変更、自動再構築、破棄まで有効です。  
これらをまたいで保持する場合は、参照ではなく複製を使ってください。

表の構築と再接続は、領域とは別に実行時だけの内部管理データを確保します。  
領域を呼び出し側が所有する場合でも、ハンドルの解放のために破棄の呼び出しが必要です。

## 選択の指針

| 状況 | 選ぶ構築方式 |
|---|---|
| 件数が実行時にしか決まらない | 自動拡張する構築 |
| 件数が設計時に決まり、内部確保でよい | 固定容量の構築 (領域の指定を省略) |
| 共有メモリやメモリ マップド ファイルへ載せる | 固定容量の構築 (領域を明示) |
| 生成時に内容が確定し、成果物として配布する | 領域へ直接書き込んで保存し、利用側は再接続 |

変更検知の粒度は、変更されたレコードだけを取り出す必要があるかどうかで選びます。  
表全体の変更有無だけを見る場合は、表全体の粒度で足ります。
