# コンソール (console) 機能仕様

## 概要

コンソールは、プログラムが接続している端末を UTF-8 と ANSI エスケープ シーケンスが使える状態にそろえる機能です。  
対象は `cplat/console/console.h` が公開する `cplat_console_*` の一群です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
API の詳細と使用例は `prod/libsrc/cplat/console/README.md` を参照してください。

## 解決する課題

Linux の端末は、既定で UTF-8 と ANSI エスケープ シーケンスを扱えます。  
Windows のコンソールは、どちらも既定では有効ではありません。

Windows では、プロセスの ANSI コード ページをマニフェストで UTF-8 にできます。  
しかし、接続先のコンソールには、それとは別に入力コード ページと出力コード ページがあります。  
マニフェストだけでは、コンソールへ書いた UTF-8 の文字列が正しく表示されません。

色やカーソル移動に使う ANSI エスケープ シーケンスも、Windows では明示的に有効化しないと文字列のまま表示されます。

さらに、権限昇格で自分自身を再起動した場合、昇格したプロセスは親のコンソールを引き継げません。  
出力先が別のウィンドウになるか、どこにも表示されなくなります。

本機能は、これらの設定を 1 か所へまとめ、Linux では何もしない形で共通の呼び出しにします。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| UTF-8 の文字列を端末へ正しく表示する | コンソールの入出力コード ページの設定 |
| 色とカーソル制御を使う | 仮想端末処理の有効化 |
| 端末の設定を元に戻す | 変更前の状態の保存と、終了時の復元 |
| リダイレクト時に余計な設定をしない | 接続先が端末である場合だけの適用 |
| 昇格したプロセスの出力を元の端末へ出す | 親コンソールへの再接続 |
| 同じコードを両プラットフォームで書く | Linux では何もしない実装 |

## 初期化と後始末

初期化は、Windows でコンソールの入力コード ページと出力コード ページを UTF-8 に設定し、標準出力と標準エラー出力の仮想端末処理を有効にします。  
すでに UTF-8 になっているコード ページは変更しません。

変更前のコード ページとコンソール モードは保存し、後始末で元に戻します。  
プログラムが端末の状態を変えたまま終了しないようにするためです。  
後始末は、通常はライブラリのアンロード時の自動解放に任せられます。

初期化を二重に呼んでも追加の設定は行いません。  
未初期化の状態で後始末を呼んでも安全です。

Linux では、初期化と後始末のどちらも何もしません。  
利用側は、プラットフォームによる分岐を書かずに同じコードを使えます。

## 端末でない場合の扱い

標準出力がパイプやファイルへリダイレクトされている場合、初期化は何も行いません。  
端末に対する設定は、端末に接続しているときだけ意味を持つためです。

初期化は、標準入力、標準出力、標準エラー出力のハンドルそのものを変更しません。  
出力先の差し替えは、この機能の責務ではありません。

## 親コンソールへの再接続

Windows の権限昇格は、昇格したプロセスを別のセキュリティ コンテキストで生成するため、親のハンドルを継承できません。  
そのため、昇格したプロセスの出力は元の端末に出ません。

本機能は、親のプロセス ID と親コンソールのウィンドウ ハンドルをコマンド ラインから受け取り、親のコンソールへ接続し直す API を提供します。  
接続後、標準入力、標準出力、標準エラー出力を親コンソールへつなぎ直します。  
検出した引き継ぎ用の引数は、引数配列から取り除いて個数を減らすため、利用側の引数解析はそれを知らずに済みます。

この API は、プログラムの開始直後、引数の解析と初期化のどちらよりも前に呼びます。

Linux では何もせず、再接続しなかったことを出力引数で返します。

## 適用範囲外

次の項目は本機能が扱いません。

- 標準出力への書き込みそのもの。`printf` や `fprintf` を置き換えません。
- 端末のサイズ取得と画面制御。プロンプト機能が扱います。
- 代替画面バッファーへの切り替え。

## 前提と制約

Windows では、利用側が `activeCodePage=UTF-8` のマニフェストを設定していることを前提とします。  
コンソールのコード ページとプロセスの ANSI コード ページは別の状態であり、両方が UTF-8 である必要があります。

親コンソールへの再接続は、権限昇格の機能が付与した引き継ぎ用の引数がある場合にだけ動作します。  
再接続後の書き込みが間欠的に失敗する事象を実機で確認しており、原因を特定できていません。  
確実に結果を表示する必要がある場合の代替手段は、[実行時支援 (runtime) 機能仕様](runtime.md) を参照してください。
