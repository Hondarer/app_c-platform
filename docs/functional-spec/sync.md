# 同期 (sync) 機能仕様

## 概要

同期は、スレッドの生成と、プロセス内およびプロセス横断の排他制御を、Linux と Windows で同じ呼び出し方にそろえた機能です。  
対象は `cplat/sync/sync.h` が公開する API 群です。

本書は、この機能が満たす要件と、その解決策として用意した機能を説明します。  
関数の宣言と契約の正本は公開ヘッダー、API の逆引きは [cplat API チート シート](../api-cheatsheet.md) です。

## 解決する課題

スレッドと排他制御の API は、Linux と Windows で名前も型も待機の指定方法も異なります。  
pthread の関数群と Win32 の同期オブジェクトは、失敗の通知方法も揃っていません。

さらに、プロセスを横断する排他は、プロセス内の排他とは別の仕組みが必要です。  
名前付きの OS オブジェクトやファイル ロックを使うことになり、その選択と後始末が利用側の負担になります。

用途によって必要な同期の強さも異なります。  
プロセス内で足りる場面にプロセス横断の仕組みを使うと、不要なコストを払うことになります。

本機能は、必要な範囲ごとに独立した種類の同期を用意し、いずれも同じ結果コードで扱えるようにします。

## 要件と機能の対応

| 要件 | 解決する機能 |
|---|---|
| スレッドをプラットフォームの差なく扱う | スレッドの生成、待ち合わせ、切り離し |
| 初期化を 1 回だけ行う | 一度だけ実行する仕組み |
| プロセス内で排他する | プロセス内ミューテックス |
| 読み取りを並行させ、書き込みだけ排他する | プロセス内読み書きロック |
| 条件が成立するまで待つ | 条件変数と、シグナルおよびブロードキャスト |
| プロセスをまたいで排他する | 識別子で開くプロセス横断ミューテックス |
| プロセスをまたいで読み書きを分ける | プロセス横断読み書きロック |
| 開いたロックを別プロセスへ渡す | ディスクリプターへの書き出しと読み込み |
| 待機に上限を設ける | すべての待機に共通のタイムアウト指定 |
| 一定時間だけ待つ | ミリ秒指定のスリープ |

## 同期の種類

同期は、有効な範囲によって 2 系統に分かれます。

プロセス内の同期は、ミューテックス、読み書きロック、条件変数です。  
生成した OS のプリミティブをそのまま使うため、プロセス横断の同期より軽量です。

プロセス横断の同期は、ミューテックスと読み書きロックです。  
識別子となる名前を指定して開き、存在しなければ生成します。  
同じ識別子を指定した別のプロセスは、同じロックを開きます。

読み書きロックは、読み取り側を並行させたい場合に使います。  
読み取りが多く書き込みが少ない共有データで、ミューテックスより待ちを減らせます。

条件変数は、待機の間だけミューテックスを解放し、通知を受けてから再取得します。  
条件が成立するまで待つ処理を、ポーリングなしで書けます。

## 待機とタイムアウト

待機を伴う API は、いずれもミリ秒のタイムアウトを受け取ります。  
無期限に待つ指定と、待たずに直ちに戻る指定も、専用の定数で表します。

タイムアウトで待機が終わった場合は `CPLAT_ERR_TIMEOUT` を返します。  
待たずに戻る試行の API は、取得できなかったことを `CPLAT_ERR_BUSY` で返します。  
どちらも失敗の種類が結果コードで区別できるため、呼び出し側は再試行と異常を分けて扱えます。

シグナルによる中断は利用側へ観測させません。  
Linux でシステム コールが中断された場合の扱いは、cplat 全体の規範に従います。

## プロセス横断ロックの受け渡し

プロセス横断ロックは識別子で開けますが、識別子を知らないプロセスへ渡したい場合があります。  
子プロセスへ引き継ぐ場合や、識別子を構成に含めたくない場合が該当します。

開いているロックは、ディスクリプターと呼ぶバイト列へ書き出せます。  
受け取った側は、そのバイト列からロックを開き直せます。  
ディスクリプターは検証可能な形式を持ち、壊れている場合は `CPLAT_ERR_CORRUPT_DESCRIPTOR` を返します。

書き出し先に NULL を渡すと、必要なバイト数だけを取得できます。

## 適用範囲外

次の項目は本機能が扱いません。

- スレッド プールとタスク スケジューリング。生成と待ち合わせだけを提供します。
- スレッドの優先度と affinity の制御。
- 再入可能なミューテックス。同一スレッドから再取得したときの動作は、プラットフォーム共通の契約として定めていません。
- デッドロックの検出。

## 前提と制約

破棄は、対象を他のスレッドやプロセスが使用していないことを確認してから呼び出してください。  
破棄の API はスレッド セーフではありません。

スレッドの切り離しは、対象のハンドルごとに 1 回だけ実行してください。

共有可能なファイル オープンは排他制御を意味しません。  
プロセス間のアクセスを直列化する場合は、プロセス横断のロックを使ってください。

## 選択の指針

| 状況 | 選ぶ同期 |
|---|---|
| 単一プロセス内の排他 | プロセス内ミューテックス |
| 単一プロセス内で、読み取りが多い共有データ | プロセス内読み書きロック |
| 条件の成立を待つ | 条件変数とプロセス内ミューテックス |
| 複数プロセスからの排他 | プロセス横断ミューテックス |
| 複数プロセスで、読み取りが多い共有データ | プロセス横断読み書きロック |

メモリ マップド ファイルを共有する場合も、必要な同期機能を呼び出し側が明示的に生成します。  
mmap ハンドルは同期ハンドルを所有しないため、同期の識別子と寿命も呼び出し側で管理してください。  
詳細は [メモリ マップド ファイル (mmap) 機能仕様](mmap.md) を参照してください。
